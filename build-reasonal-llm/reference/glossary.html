术语表 Glossary

全书通用 · 已覆盖 ch1–8 术语以本书用法为准（BRM）

每课出现的新术语都会收录在这里。中文课、英文术语——因为论文、代码、报错信息里用的都是英文。出处缩写 BRM = Build a Reasoning Model (From Scratch)。

推理核心 · Reasoning（ch1）

推理 reasoning
（工程定义）模型在给出最终答案之前生成中间步骤。中间步骤可以展示给用户，也可包在 <think>…</think> 这类特殊标签里隐藏。本质：把 token 花在中间解题过程上，而不是直接跳到结论。BRM §1.1
思维链 chain-of-thought, CoT
中间步骤式生成的俗称：模型"一步一步思考"，把推理过程显式写出来。既可指一种提示技术（"think step by step"），也可指推理模型的输出形态。BRM §1.1
推理模型 reasoning model
经过训练或提示改进、能稳定产生上述中间步骤的 LLM，在数学/编码/逻辑难题上准确率更高。例：OpenAI o1/o3、DeepSeek-R1、Qwen3（思考模式）。BRM §1.1
思考标签 <think> tokens
把中间推理步骤与最终答案分隔开的特殊标记。对用户可隐藏，但模型生成时真实存在；蒸馏数据用它包裹教师思考过程（ID 151667/151668），ch7 还用它设计过格式奖励。BRM §7.6, §8.3
模式匹配 pattern matching
模型基于训练数据中的统计关联续写文本，而非显式应用逻辑规则。"德国的首都是柏林"= 强统计关联的回忆，不是逻辑推导。BRM §1.4
封闭世界 / 开放世界 closed-world / open-world
封闭世界：只依据题给前提做推论（"所有鸟都会飞+企鹅是鸟 ⇒ 企鹅会飞"是有效推论）。开放世界：允许背景知识参与，可能与前提冲突。好系统应察觉矛盾。BRM §1.4

训练管线 · Training Pipeline（ch1）

预训练 pre-training
在海量无标注文本（TB 级、万亿 token）上做下一 token 预测，学到语言模式与涌现能力。成本：数千 GPU · 数月 · 数百万美元。产出：base model。BRM §1.2
后训练 post-training
在 base model 之上让它变得可用：= 指令微调（SFT）+ 偏好微调（preference tuning，常经 RLHF 实现）。BRM §1.2
指令微调 supervised fine-tuning, SFT / instruction tuning
用"指令→理想回答"的标注数据做监督微调，让模型会听指令（问答、摘要、翻译）。蒸馏本质上就是拿教师数据做 SFT。BRM §1.2, §8.1
RLHF Reinforcement Learning with Human Feedback
用人类对回答的评估/排序（常先训练奖励模型替代人工）作为奖励信号做强化学习。用于常规 LLM 的偏好对齐。BRM §1.3, §6.1
RLVR Reinforcement Learning with Verifiable Rewards
用自动验证器（如：数学答案对不对、代码能否通过测试）作为奖励信号做强化学习。比人类反馈更客观、可规模化，是推理模型训练（DeepSeek-R1、本书 ch6–7）的核心。BRM §1.3, §6.1

改进推理的三大流派 · Three Approaches（ch1, 终局对比见 0016）

推理时算力扩展 inference-time compute scaling / test-time scaling
不改权重，在推理时多花算力换性能：CoT 提示、温度采样、self-consistency 投票、self-refinement。本书 ch4–5。书中最佳：52.0%（CoT+投票 n=10）。BRM §1.3
强化学习（推理） reinforcement learning for reasoning
改权重：用奖励信号（常为 RLVR）让模型在试错中学会并精炼推理策略。本书 ch6–7 的 GRPO，50 步 15.2%→47.4%。BRM §1.3
蒸馏 distillation
用更强的教师模型生成高质量推理轨迹，对小模型做 SFT，把推理模式"搬"进小模型。与传统深度学习蒸馏（学 logits）不同，本书的 hard 蒸馏只学输出文本。ch8：15.2%→45.0%。BRM §1.3, §8.8

生成机制 · Generation（ch1–2）

token
模型处理文本的最小单位：一个整词、词的一部分或标点。文本先由 tokenizer 切成 token 再转成 ID。BRM §1.2
自回归生成 autoregressive generation
每次基于已有序列预测下一个 token，逐个追加，循环往复。LLM"推理"也是这样逐 token 产生的——因此不保证逻辑正确。BRM §1.1, fig 1.8
前向传播 forward pass
模型对当前序列做一次完整计算得到下一个 token 的分布。生成 N 个 token ≈ N 次前向传播——这是推理模型更贵的第一个原因。BRM §1.6
logits
模型输出层给出的每个候选 token 的原始分数（未归一化）。Qwen3 0.6B 每步输出 151,936 个。softmax 归一化后才是概率。BRM §4.4
贪心解码 greedy decoding / argmax
每步选 logits 最大的 token。确定、可复现，但同一题永远同一个答案；投票类方法必须绕开它。BRM §2.4, §4.4
KV 缓存 KV cache
缓存已算过的 key/value 投影，新 token 只需算增量——把每步成本从 O(L²) 降到 O(L)。配 torch.compile 后书里 5 t/s → 68 t/s（13 倍）。BRM §2.6–2.7
EOS token end of sequence
终止符（Qwen3 为 <|endoftext|>，ID 151643）。RL 训练时保留它在 rollout 里，防止模型忘怎么停。BRM §2.4, §6.5

评估 · Evaluation（ch3）

MATH-500
书中的标准评估集：500 道数学题，含 problem/answer/solution 字段。全书所有准确率都在它上量。base 15.2% / reasoning 48.2% 是两大基准线。BRM §3.1
\boxed{} 抽取
答案抽取约定：取最后一个 \boxed{...}（按括号深度解析嵌套），再经 LaTeX 规范化后与标准答案比对。BRM §3.4–3.6
验证器 verifier
"已知标准答案"时自动判对错的程序（LaTeX 规范化 + SymPy 符号等价）。评估时当裁判，RLVR 时当奖励来源——全书地基。BRM §3.5–3.7, §6.6
提示敏感度 prompt sensitivity
同一道题换模板准确率可 ±50%。评估必须固定模板，否则数字不可比；工作里看别人报的分数必先问模板。BRM §3.8
数据泄漏 data leakage
评估题混进训练集导致虚高。MATH 训练 12,000 题与 MATH-500 互不重叠就是为了防它（ch6 RL 和 ch8 蒸馏都用这批训练题）。BRM §6.4

解码与采样 · Decoding & Sampling（ch4）

温度缩放 temperature scaling
logits ÷ T 后再 softmax：T<1 分布更尖（更确定），T>1 更平（更多样），T=0 等价贪心。书里 0.7–1.0 区间性能最稳。BRM §4.4.2
Top-p / 核采样 nucleus sampling
按概率降序累加，只保留累积概率达 p 的最小 token 集合，其余清 -inf 再归一化采样——砍掉长尾垃圾 token。与固定个数的 top-k 相比保留集大小自适应。BRM §4.5
CoT 提示 CoT prompting
在 prompt 末尾加 "Explain step by step." 等引导，让 base 模型先写过程再给答案：15.2%→40.6%，代价约 8 倍生成时间；推理模型已内化此能力，加了反而 overthinking。BRM §4.2–4.3
Self-consistency 自洽投票
温度采样 N 份 CoT 解答，抽取各自答案，多数票定最终答案。书里 n=10 到 52.0%（超过单次 reasoning 的 48.2%），但耗时 ×10。有效性前提：错误答案彼此分散、正确答案趋同。BRM §4.7
过度思考 overthinking
简单题也拉满思考预算：准确率不升、token 费用狂涨。对应"该 1 秒答的别想 1 分钟"。自适应推理预算（GPT-5 auto 模式）就是解药。BRM §8.9

概率与打分 · Probability & Scoring（ch5）

log-probability（logprob）
概率取对数，全在负数域：越接近 0 模型对该 token 越有信心。序列 logprob = 各 token logprob 之和。BRM §5.4
交叉熵 cross-entropy
= 正确 token 的负平均 logprob。既是第 5 课的打分器，也是蒸馏训练的损失函数（书例：-16.63÷10≈1.68，与 F.cross_entropy 完全一致）。BRM §8.6
答案均值 logprob average logprob
序列 logprob ÷ 答案 token 数，消除长度偏差才能跨样本比较。诚实教训：它作为答案打分器在书中表现最差（≈不加打分器），"听起来合理"≠"有用"。BRM §5.4–5.5
LLM-as-a-judge / 打分器 scorer
"不知道标准答案"时用模型给候选答案打分。启发式 prompt 版（检查三要素）在书中最有效（reasoning 模型 25.0%→57.8%），平均 logprob 版反而最差。BRM §5.5–5.6
Self-refinement 自我改进
生成→打分→ critique → refine 的循环。仅当打分器能区分好坏时有效；打分器弱时多轮反而降分。RL 本质上就是"可微版 + 试错版"的同思想。BRM §5.7

RL 与 GRPO · Rollouts & Rewards（ch6–7）

策略 policy
RL 黑话里"被训练的模型"本身。LLM 场景：policy = 当前权重的 LLM，输出 token 分布即策略的动作分布。BRM §6.1
rollout
让当前 policy 对一道题采样一个完整回答（就是第 8 课的温度采样循环）。GRPO 每题采 G 个（书里 8 个）。BRM §6.5
优势 advantage
组内相对分：ri − mean(组) 再除以 std（GRPO 风格）。比绝对奖励稳，天然形成"好的加强、差的削弱"。BRM §6.6
策略梯度损失 policy gradient loss
pg_loss = -(advantage.detach() × logprob).mean()：把高优势 rollout 的每个 token 概率推高、低优势压低。BRM §6.7
GRPO Group Relative Policy Optimization
DeepSeek 推广的 RLVR 算法：组内归一化算优势、去掉 PPO 的 value model、（原版带 KL 项）。书里 50 步：15.2%→47.4%。BRM §6.8
KL 散度 KL divergence
两个分布的差异度量。RL 里常用于把新策略拴在参考模型附近防跑飞。书里的实验：对 0.6B 小模型加 KL 项反而灾难性崩溃（长度暴涨、熵爆炸→乱码）。BRM §7.3
裁剪比率 clipped policy ratio
限制新旧策略概率比 π_new/π_old 的单步移动幅度（书里 clip 到 [0.7, 1.4]），防止单批 rollout 过度拉扯权重。修复了书中 step 400 后的性能下滑。BRM §7.2
奖励黑客 reward hacking
模型钻奖励函数空子拿分而不解决任务。书例：格式奖励（think 标签 151667/151668）让模型学会只输出标签不推理。奖励设计必须验证"分数涨=能力涨"。BRM §7.6
熵 entropy
输出分布的不确定度。训练崩坏信号：熵爆炸=输出近乎均匀随机（乱码）；熵过低=模式坍缩。健康训练中熵温和上升（探索更多样解法）。BRM §7.4–7.5

蒸馏 · Distillation（ch8）

教师 / 学生 teacher / student
教师 = 强但贵的大模型（书里 DeepSeek-R1 671B，MATH-500 91.2%）；学生 = 小而廉的模型（Qwen3 0.6B base）。学生学教师的推理轨迹而非教师本身。BRM §8.1
Hard / Soft 蒸馏
Hard：学生拿教师生成文本做 SFT 目标（本书/R1 路线）；Soft：对齐教师完整概率分布（KL，需 logits）。Hard 更实用：文本便宜好存，API 不给 logits。BRM §8.1
答案-only 损失 answer-only loss
cross-entropy 只算教师答案段（含 think 思考），prompt 段不算——prompt 是给定上下文，不是要学的东西。同第 9 课打分只看答案段的思想。BRM §8.6
训练/验证损失 train / validation loss
train loss 在当前优化中的样本上算（噪声大）；val loss 在固定留出集上算（干净）。蒸馏训练盯 val loss：骤降后趋平=健康，继续训收益递减。BRM §8.7–8.8
同门教师效应
师生同家族（tokenizer、提示惯例、行文风格一致）蒸馏效果显著更好：Qwen→Qwen 45.0% vs R1→Qwen 33.6%。选教师，同家族优先。BRM §8.8
