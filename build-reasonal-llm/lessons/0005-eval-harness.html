📖 BRM §3.2–3.3, §3.8–3.9 ⏱ 25–35 分钟 🎯 收获：一条可复用的评估管线 + 两个反直觉的评估教训

为什么学这个：上一课造好了尺子（verifier），这一课把它装上流水线：数据集 → prompt 模板 → 生成 → 判分 → 准确率。以后每一课的改进（CoT、投票、GRPO……）都要回到这条管线上验证有没有真提升。同时你会撞上两个工作里极其常见的坑：prompt 敏感性和小样本噪声。

01MATH-500：为什么是它

MATH-500 是从原版 MATH 数据集采样的 500 道题（该切分最初由 OpenAI 的 PRM800K 仓库提出）BRM §3.8。选它三个理由：

  1. 大小合适：500 题有统计意义，又不至于每次评估跑半天；
  2. 干净：后面的训练集取自原 MATH 的不重叠子集，MATH-500 保持 held-out；
  3. 行业标准：推理模型文献普遍用它，结果可直接对比。

每条数据三个关键字段：problem（题面）、answer（标准答案）、solution（人工解题过程——本章不用，第 15 课蒸馏时会用到）BRM §3.8。

02Prompt 模板：让答案长在固定位置

验证器期望 \boxed{} 格式，所以用模板明确要求BRM §3.9, listing 3.13：

def render_prompt(prompt):
    return (
        "You are a helpful math assistant.\n"
        "Answer the question and write the final result on a new line as:\n"
        "\\boxed{ANSWER}\n\n"
        f"Question:\n{prompt}\n\nAnswer:"
    )
教训一：模板不是中性的书中实测（M4 芯片）：这个"逼短答案"的模板让 base 模型答 \boxed{10}——快，但错；而不加模板时模型写得长，反而答对 14/3。更狠的数据：**去掉模板 base 准确率 +50%，reasoning 模型 −40%**；把 "Question:" 换成 "Problem:"，base +20%，reasoning −30%。BRM §3.9 侧栏

结论：小模型对 prompt 措辞高度敏感；模板选择本身是一个要被评估的实验变量，没有免费午餐。

03评估主循环

核心逻辑 20 行——就是第 4 课流水线 × 500BRM §3.9, listing 3.15：

def evaluate_math500_stream(model, tokenizer, device, math_data, ...):
    for i, row in enumerate(math_data, start=1):
        prompt = render_prompt(row["problem"])          # ① 套模板
        gen_text = generate_text_stream_concat(         # ② 生成（ch2 的函数）
            model, tokenizer, prompt, device, max_new_tokens=512)
        extracted = extract_final_candidate(gen_text)   # ③ 抽取
        is_correct = grade_answer(extracted, row["answer"])  # ④⑤ 归一化+判分
        num_correct += int(is_correct)
        f.write(json.dumps({...}) + "\n")               # ⑥ 每题落盘 jsonl
    print(f"Accuracy: {num_correct/num_examples*100:.1f}%")

工程细节值得抄走：逐题写 JSONL（跑崩不丢结果、事后可逐题分析）、ETA 进度、verbose 开关（看 token 流确认没卡死）BRM §3.9。

三个观察：

  • 推理版确实强（500 题上 15.3% → 50.8%）——这就是"官方用推理方法训练后"的差距，也是我们接下来 11 课要亲手复现的方向；
  • 代价是时长：推理版回答长得多，500 题从 13 分钟变 3 小时（batch 化脚本可压到 14.6 分钟BRM §3.9 TIP）——第 1 课说的"两个贵"在这里具象化了；
  • 10 题上的 30% ≠ 500 题的 15.3%——见下面教训二。
教训二：小样本会骗人10 题子集给 base 打出 30%，全集只有 15.3%——3 题的运气差就被放大成 15 个百分点。书里用 10 题是为了演示速度，并明确提醒子集不一定有代表性（练习 3.3 让你自己验证）。工作启示：汇报数字前先问"多少题、几次运行、方差多大"。
🧰 工程锦囊逐题 JSONL 落盘的另一个用途：跑完后用脚本统计"抽取失败率""平均答案长度""按题型/难度分层准确率"——第 14 课追踪 GRPO 训练指标时的套路与此同源。

05检索练习

一句话带走 评估管线 = 数据集 × prompt 模板 × 生成 × 验证器，产出准确率。两个铁律：模板本身是实验变量（对 base 和 reasoning 影响可能相反）；小样本数字不可信（30%@10 ≠ 15.3%@500）。
