01裸循环慢在哪：重复计算

回看第 2 课的循环：每生成一个新 token，都要把整个序列（prompt + 已生成部分）重新喂进模型做完整前向传播。但注意——序列里除了最后那个新 token，其余所有 token 的中间计算结果和上一轮一模一样，却被原样重算了一遍BRM §2.8。

02KV Cache：把中间结果存起来

Transformer 注意力里每个 token 都会产生 Key/Value 向量。KV cache 的思路：第一轮照常算完整输入，把每层的 K、V 缓存；之后每轮只把新 token 喂进模型，旧 token 的 K/V 直接查缓存——省掉全部重复计算。总复杂度从 O(n²) 降到约 O(n)BRM §2.8。

代码改动小得惊人——和第 2 课的函数几乎逐行相同，只加了 cacheBRM §2.8, listing 2.4：

from reasoning_from_scratch.qwen3 import KVCache

@torch.inference_mode()
def generate_text_basic_stream_cache(model, token_ids, max_new_tokens, eos_token_id=None):
    model.eval()
    cache = KVCache(n_layers=model.cfg["n_layers"])   # 每层一份 K/V 缓存
    model.reset_kv_cache()
    out = model(token_ids, cache=cache)[:, -1]        # 首轮：完整输入 + 填充缓存
    for _ in range(max_new_tokens):
        next_token = torch.argmax(out, dim=-1, keepdim=True)
        if eos_token_id is not None and torch.all(next_token == eos_token_id):
            break
        yield next_token
        out = model(next_token, cache=cache)[:, -1]   # 之后：只喂新 token！

重要 sanity check：加缓存后生成的文本与不加时逐字相同——KV cache 是纯计算复用，不改变任何数学结果。如果你加了缓存输出变了，说明实现有 bug。BRM §2.8

03torch.compile：把 Python 开销压掉

torch.compile 分析模型计算图，把成组操作融合成优化内核，减少 Python 解释开销——对"同一模型反复调用"的生成循环收益明显BRM §2.9：

model_compiled = torch.compile(model)   # 一行

两个坑：① 首次运行慢（编译需要时间），基准测试要跑 3 次丢弃第一次（warm-up）；② Apple Silicon 遇 InductorError → 升级 PyTorch ≥ 2.9。BRM §2.9

05检索练习

一句话带走 KV cache 存旧 token 的注意力中间量，每轮只算新 token（O(n²)→O(n)，输出不变）；torch.compile 融合算子压 Python 开销（首次慢，之后快）。两者叠加 ≈ 13 倍。
