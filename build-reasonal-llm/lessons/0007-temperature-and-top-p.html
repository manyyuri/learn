第 7 课 · 温度与 Top-p：驯服下一个 token 的随机性

📖 BRM §4.4–4.5 ⏱ 35–45 分钟 🎯 收获：彻底搞懂 logits→温度→softmax→top-p→采样 全链路

为什么学这个：到目前为止我们一直用 argmax（贪心）——同一道题永远得到同一个答案。但下一课的投票需要模型能给出不同的解法路径。控制"多不一样"的两个旋钮就是 temperature 和 top-p。这两个参数你在任何 LLM API 里都见过（OpenAI、Anthropic、Qwen……）；这课之后你不再靠玄学调它们。

01全景：下一个 token 是怎么选出来的

以 "The capital of Germany is" 为例，完整链路五步BRM §4.4.1–4.4.3：

① logits151,936 个原始分数

→
③ softmax变成概率分布
→
④ top-p 过滤砍掉长尾

图 1 · 采样解码管线。argmax 贪心 = 跳过②④⑤直接取最大；采样解码 = 全程走完。BRM fig 4.8/4.16
softmax 回顾softmax 把任意实数分数变成合法概率（非负、总和 1）：每个取 exp(zᵢ) 再除以总和。谁的 logit 高谁概率大，但都保留可能性——这是"采样"的物理基础。BRM §4.4.3 侧栏

02温度：除一下，改变峰谷比

实现只有一行——logits 除以温度BRM §4.4.2, listing 4.4：

def scale_logits_by_temperature(logits, temperature):
    if temperature <= 0:
        raise ValueError("Temperature must be positive")
    return logits / temperature

但效果是乘法级的。书里的实测（"Berlin" 的采样概率）BRM §4.4.2–4.4.3：

温度分布形状"Berlin" 概率行为
→ 0尖成针→ 100%等价于贪心 argmax
0.35很尖~42%稳定，偶有变化
1.0原样（基准）模型原生置信度
5.0摊平0.03%1000 次采样全是乱码 token

直觉：温度缩放的是 logits 之间的"落差"。T<1 拉大落差 → 头部 token 更霸道；T>1 压平落差 → 尾部 token 也有机会。T=5 时书里采出的下一个词是 "mistress"——语法上是个词，语义上完全跑偏BRM §4.4.3。

🌡 为什么叫温度借自统计物理：温度越高，系统粒子越"躁动"。这里温度越高，token 选择越随机。BRM §4.4.2 侧栏

03Top-p：砍掉长尾再采样

温度的副作用：摊平后，那些概率极低的"垃圾 token"也获得了非零概率，偶尔会被抽中。top-p（nucleus sampling）的解法：只保留累积概率达到 p 的最小 token 集合，其余清零，重新归一化后采样BRM §4.5。

四步实现（10-token 玩具词表演示）BRM §4.5.1, listing 4.10–4.15：

def top_p_filter(probas, top_p):
    if top_p is None or top_p >= 1.0:
        return probas
    sorted_probas, sorted_idx = torch.sort(probas, dim=1, descending=True)  # ① 降序排
    cumprobas = torch.cumsum(sorted_probas, dim=1)                          # ② 累积和
    prefix = cumprobas - sorted_probas          # ③ 前缀（不含自己）< top_p 的保留
    keep = prefix < top_p                       #    —— 跨过阈值的那只也保留
    keep[:, 0] = True                           #    保底：第一名永远保留
    kept_sorted = torch.where(keep, sorted_probas, torch.zeros_like(sorted_probas))
    filtered = torch.zeros_like(probas).scatter(1, sorted_idx, kept_sorted) # ④ 回原位
    denom = torch.sum(filtered, dim=1, keepdim=True).clamp_min(1e-12)
    return filtered / denom                     # ⑤ 重归一化

书中效果（T=0.35, p=0.8）：过滤前 1000 次采样里 "Berlin" 435 次、下划线一堆、还有 Munich/Hamburg；过滤后只剩 "Berlin" 534 次 + 下划线——Munich/Hamburg 这类低概率项被砍掉了BRM §4.5.1。

top-p vs top-ktop-k 保留固定个数 k 个最高分 token；top-p 保留可变个数——置信分布尖时留几个，摊平时留几百个。top-p 对分布形状自适应，如今更主流。BRM §4.5.2 侧栏

04装进生成函数

在 KV cache 版生成循环里替换 argmax 分支BRM §4.4.4/4.5.2, listing 4.16：

@torch.inference_mode()
def generate_text_top_p_stream_cache(model, token_ids, max_new_tokens,
                                     eos_token_id=None, temperature=0., top_p=None):
    model.eval()
    cache = KVCache(n_layers=model.cfg["n_layers"])
    model.reset_kv_cache()
    out = model(token_ids, cache=cache)[:, -1]
    for _ in range(max_new_tokens):
        if temperature is None or temperature == 0.0:
            next_token = torch.argmax(out, dim=-1, keepdim=True)   # 贪心
        else:
            logits = scale_logits_by_temperature(out, temperature) # ②
            probas = torch.softmax(logits, dim=-1)                 # ③
            probas = top_p_filter(probas, top_p)                   # ④
            next_token = torch.multinomial(probas.cpu(), num_samples=1)  # ⑤
        if eos_token_id is not None and torch.all(next_token == eos_token_id):
            break
        yield next_token
        out = model(next_token, cache=cache)[:, -1]
实践要点① temperature=0.0 ≈ 贪心（argmax 分支）；② 书中实测在 cuda/mps 上 multinomial 大样本不稳定甚至崩溃（PyTorch 2.9），故采样搬回 CPU 做；③ 常用起点：T ∈ [0.5, 0.9]，p ∈ [0.7, 0.9]；答案太雷同 → 调高，答案开始胡说 → 先降 T。BRM §4.4.4/4.6 侧栏

05检索练习

一句话带走 温度 = logits ÷ T，调峰谷比（低稳高浪）；top-p = 砍掉累积概率 p 之外的长尾再归一化。贪心 vs 采样的全部区别，就在这两步。
