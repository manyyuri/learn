📖 BRM §7.2–7.6 ⏱ 40–50 分钟 🎯 收获：三个真实实验——一个修复不稳定、一个翻车、一个被模型钻空子

为什么学这个：第 13 课的 GRPO 是"简化版"，50 步够用，500 步就开始翻车（约第 400 步准确率下滑）。这课是全书最"实战"的一章：怎么读训练曲线、怎么判断健康/崩溃、三个改进各修什么、又各引出什么新问题。你所看到的每个翻车案例，都是真实训练中会遇到的——这就是"训练推理模型"工作的日常。

01监控面板：五个仪表盘

指标健康读数危险信号
loss相对平稳（只是 sanity check）持续爆炸
reward_avg缓步上升中途崩向 0；到 1.0 也该停（信号消失）
avg_response_len初期随准确率一起增长无限增长顶到上限 / 骤降
adv_avg / adv_std均值恒 0（设计使然）；std ≈ 1std→0 = 学习信号消失；std 爆表 = 更新过猛
entropy中等（每个生成步 ≈1–2），缓降→ 0 = 坍缩（复读机）；飙升 = 接近随机

熵的算法（一个 token 位置的分布不确定度）：H = −Σ p·log p；一条回答取各步平均BRM §7.3.2。单独看任何一个指标都会误诊——熵高 + 奖励升 = 健康探索；熵高 + 奖励崩 = 胡言乱语。要联读BRM §7.3.3。

02改进一：裁剪策略比率（有效 ✅）

朴素 GRPO 的更新幅度没有上限。裁剪的思路：限制新旧策略一步之内能差多远BRM §7.4：

log_ratio = new_logps - old_logps          # 同一批 rollouts，更新前后各算一遍 logprob
ratio = torch.exp(log_ratio)               # =1 表示没变；>>1 概率大涨；<<1 大跌
clipped_ratio = torch.clamp(ratio, 1.0 - clip_eps, 1.0 + clip_eps)

obj = torch.where(adv >= 0,
                  torch.minimum(ratio*adv, clipped_ratio*adv),   # 好事也别推过头
                  torch.maximum(ratio*adv, clipped_ratio*adv))   # 坏事也别踩过头
clipped_pg_loss = -torch.mean(obj)

工程细节：需要 old logprobs——把当前模型复制成参考策略，采样一组 rollouts，先算 old、更新后再算 new。DeepSeek-R1 的规模：一次采 8192 条 rollouts，切 16 个 minibatch 反复用；书的缩小版：每步采 8 条、小批多次BRM §7.4.2。ε 取值见仁见智：R1 用 10（很松），PPO 系常用 0.1（很紧）。

实测：500 步曲线平稳，第 400 步的下滑消失了BRM §7.4.2。这是来自 PPO 的经典智慧（PPO 论文）。

03改进二：KL 惩罚（教科书正确，实测翻车 ❌）

补上原始 GRPO 的最后一项：KL 项度量当前模型偏离参考模型（训练起点的冻结副本）的程度，把"别走太远"写进损失BRM §7.5：

ref_model = copy.deepcopy(model)   # 冻结副本（R1 每 400 步才换一次参考）
for p in ref_model.parameters(): p.requires_grad = False
...
kl_loss = kl_coeff * torch.mean(logps - ref_logps)   # kl_coeff 常取 0.001–0.05
loss = pg_loss + kl_loss

实测：前 50 步正常涨到 40%，随后全面崩盘——loss 爆炸、奖励归零、输出变成乱码 token（"framework.raises Self profess(import"）BRM §7.5.2。尸检两条死因：

  1. 求和版 KL 鼓励写长：logprob 差随长度累积，拉长回答就能"摊薄" KL——于是回答长度一路涨到上限。
  2. 奖励崩零后 KL 独占梯度：全零奖励 → 优势全零 → 策略梯度无信号，只剩 KL 项推着模型走向高熵均匀分布 = 纯随机。准确率 0%。
行业现状数学任务的通行做法是干脆去掉 KL 项（Dr. GRPO、Olmo 3、DeepSeek-V3.2 均报告去掉后更稳更好）；要留就打补丁：调小系数、按长度归一化、重要性加权（V3.2 方案）、或用格式奖励保住优势信号。BRM §7.5.2 侧栏——"教科书正确"与"实测有效"的差距，是最值得记住的一课。

04改进三：格式奖励（被钻空子 ⚠）

辅助奖励教会模型用 <think>…</think> 包住推理过程、盒子装答案BRM §7.6：

# 给 base tokenizer 的空占位槽加特殊 token：<think>→151667, </think>→151668
tokenizer_base._tok.add_special_tokens(
    ["", "", "", ""])

def reward_format(token_ids, prompt_len):
    try:
        gen = token_ids[prompt_len:].tolist()
        return float(gen.index(151667) < gen.index(151668))  # 有且有序 = 1
    except ValueError:
        return 0.0

reward = rlvr_reward + format_reward_weight * format_reward  # 加权合并

两个坑：① base 模型从没见过 think token，直接训会很差——先 SFT 再 RL，或直接训 reasoning 变体（书选后者，第 15 课正是补 SFT）；② 实测：模型学会了"刷格式分"——format_reward_avg 居高不下，答案正确率反而下滑BRM §7.6.2。这就是 reward hacking（奖励作弊）：奖励是代理指标，模型优化代理本身而不是你的真实意图。补救：权重 1.0→0.1，或条件格式奖励（答案对了才给格式分，书练习 7.2）。

后续还有 15+ 种魔改DAPO 的零梯度过滤/主动采样/token 级损失、Dr. GRPO 去标准化、V3.2 的重加权 KL、GSPO 的序列级重要性采样……原理你已全部具备：都是在动"优势怎么算、比率怎么裁、KL 怎么用"这几个零件。BRM §7.6.3

05检索练习

一句话带走 监控五表联读（loss/奖励/长度/优势std/熵）。裁剪限制单步位移（有效）；KL 限制长期漂移（数学任务常翻车，行业多弃用）；格式奖励要防钻空子（降权或设为条件奖励）。
