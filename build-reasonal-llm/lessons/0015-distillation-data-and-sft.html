为什么学这个：R1 有 6710 亿参数，你部署不起——但 DeepSeek 团队的做法是让它当老师，把推理能力蒸进小模型。R1 论文实测：蒸馏出的小模型胜过同尺寸纯 RL 训练的模型BRM §8.1。对你的工作这是最可行的路线：不用 RL 基础设施、不用奖励设计，只需要 API 预算和一个标准微调循环。

01Hard vs Soft 蒸馏

Hard 蒸馏（本课）Soft 蒸馏
学生学什么教师生成的文本（token 即目标）教师的完整概率分布（KL 对齐）
本质合成数据上的 SFT分布匹配
需要教师只要输出文本要 logits（API 一般不给）

实践中 hard 蒸馏占绝对主流——文本便宜好存，logits 又贵又难拿BRM §8.1。DeepSeek-R1 的小模型们全是 hard 蒸馏。⚠️ 注意：用专有模型（OpenAI/Anthropic）的输出做训练数据，先查服务条款。

和 RLVR 的账面对比同一块 MATH 训练集：GRPO 训练 ~12 小时 / 70GB 显存；蒸馏 ~3 小时 / 15GB（教师数据已提前生成，$50 API 费）——因为最贵的"生成"被一次性挪到了训练之外。BRM §8.1/8.8

02造数据：让 R1 当老师

12,000 道 MATH 训练题（与 MATH-500 不重叠，同第 12 课）逐题喂给 DeepSeek-R1，收集回答。每条记录四个字段BRM §8.3：

{"problem":        "Sam is hired for a 20-day period...",   # 题目
 "gtruth_answer":  "6",                                    # 标准答案（用于验证教师）
 "message_thinking": "Okay, let's see. Sam was hired...",    # 教师的推理过程 ← 精华
 "message_content":  "Sam worked x days and did not work...", # 教师的最终解答}

教师质检：R1 在这批题上 90.6% 正确（MATH-500 上 91.2%）——作为对照，学生 base 是 15.2%，官方 0.6B reasoning 是 50.8%BRM §8.3。训练目标拼装：

def format_distilled_answer(entry):
    return (f"<think>{entry['message_thinking']}</think>\n\n"
            f"{entry['message_content']}")          # 推理装进 think 标签，答案在外

<think> 标签不参与训练本身，但让推理与答案结构分离——部署时 UI 可以只展示答案、折叠推理（ChatGPT 就是这么做的）BRM §8.3。

03预处理：一个数字暴露的行业真相

tokenize（reasoning 版，原生支持 think 标签 + chat 模板）后统计长度BRM §8.4.3：

  • 平均 2,946 tokens——这就是推理模型为什么贵：一道题近 3k token 的思考
  • 最长 42,005 tokens（一道题想了一天）
  • 过滤到 ≤2048：12000 → 6695 条（砍掉 44%！）→ 再切 6670 训练 / 25 验证

长度过滤是蒸馏在消费级硬件上可行的关键杠杆——也意味着我们的学生天生是"简短型"推理者。

图 1 · CE = 正确 token 的负平均 log-prob。书例：seq logprob −16.63 ÷ 10 个答案 token ≈ 1.68，与 F.cross_entropy 输出完全一致。
def compute_example_loss(model, example, device):
    token_ids = example["token_ids"]
    input_ids  = torch.tensor(token_ids[:-1]).unsqueeze(0)  # 错位一格：预测下一个
    target_ids = torch.tensor(token_ids[1:])
    logits = model(input_ids).squeeze(0)
    answer_start = max(example["prompt_len"] - 1, 0)         # prompt 段不罚
    loss = F.cross_entropy(logits[answer_start:], target_ids[answer_start:])
    return loss

prompt 不算损失（它是给定的上下文，不是学生要学的），只对教师答案算——这和第 9 课 avg_logprob 只取答案段如出一辙。

05训练循环：老朋友全家福

比 RLVR 循环更简单——没有采样、没有奖励、没有优势，就是标准监督训练循环BRM §8.7：按 epoch 轮转（每轮洗牌）→ 逐例算 CE loss → backward → 裁剪 → optimizer.step() → 定期在验证集上评估 + 存 checkpoint。超参：lr=1e-5、grad_clip=1.0、3 epochs。

看板只有两个数：train_loss（噪声大）和 val_loss（25 条留出集，干净）——val loss 是主信号：骤降后趋平 = 健康的学习曲线BRM §8.8。

M1 Pro 实跑建议书配置（2048 上限）需 ~15GB 显存，16GB 的 Mac 勉强够。安全做法：max_len 降到 512 或 1024（数据多留一些），或 batch=1 逐例训练（书即是）。教师数据 107MB 可从 HuggingFace rasbt/math_distill 直接下载，不用自己生成。

06检索练习

一句话带走 Hard 蒸馏 = 拿教师（R1）的「推理过程 + 答案」当 SFT 数据：think 标签分离思考、长度过滤控成本、answer-only cross-entropy（= 负平均 logprob）做损失、标准循环训练。数据一次性、训练便宜、可迭代。
