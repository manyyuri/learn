第 13 课 · GRPO 实操 II：损失、训练循环与 15%→47%

📖 BRM §6.8–6.12 ⏱ 40–50 分钟 🎯 收获：拼出 GRPO 损失 + 标准训练循环，跑出接近官方的推理模型

为什么学这个：这是全书的高潮——50 步训练，把 15.2% 的 base 模型变成 47.4% 的推理模型，逼近官方 reasoning 版的 48.2%BRM table 6.1。而且书的训练循环在你 M1 Pro 的 MPS 上真实可跑（书里自己就演示了 MPS 输出）。

01阶段四：sequence logprob（sum 不 mean）

第 9 课的 avg_logprob_answer 取平均（为了公平比较长短答案）。GRPO 里改成求和BRM §6.8：

def sequence_logprob(model, token_ids, prompt_len):
    logits = model(token_ids.unsqueeze(0)).squeeze(0).float()
    logprobs = torch.log_softmax(logits, dim=-1)
    selected = logprobs[:-1].gather(1, token_ids[1:].unsqueeze(-1)).squeeze(-1)
    return torch.sum(selected[prompt_len - 1:])   # ← sum，不是 mean

两个理由BRM §6.8：① 优势是发给整条序列的（一个 rollout 一个 advantage），logprob 就该是整条序列的联合似然，不该按长度摊薄；② 平均会"重新缩放学习信号"，长短回答贡献失衡。注意没有 @inference_mode——梯度要能穿过 sum 流回模型参数（输出带 grad_fn=SumBackward0）。

四个 rollout 的 logprobBRM §6.8：

rolloutseq logprob奖励
\boxed{83}（最短）−7.921
The correct answer is \boxed{83}−20.151
The final answer is 83−16.610
We get \boxed{38}（错的）−23.370

越长越负（每 token 都在扣分）——sum 版 logprob 隐性偏好简洁回答：同样分数下，模型倾向更短的解法，除非写长能换更高奖励。

02阶段五：policy gradient 损失

logps = torch.stack(rollout_logps)                    # [-7.92, -20.15, -16.61, -23.37]
pg_loss = -(advantages.detach() * logps).mean()       # = -2.576

三个成分逐一拆BRM §6.9：

  • advantages.detach()：优势是"固定的学习信号"，切断它的梯度——只让梯度通过 logprob 更新模型。
  • 相乘：优势正的 rollout，提高它所有 token 的概率；负的压低。直觉：−A·logp 最小化 ⇔ 高优势回答高概率。
  • 负号：PyTorch 优化器只会最小化；目标本是最大化（优势加权的 logprob），翻个符号等价换向。

compute_grpo_loss 把五阶段打包：采样（model.eval()）→ 逐条算奖励和 logprob → 组内标准化优势 → 拼损失，返回 loss、rewards、advantages、samples 一揽子诊断信息BRM §6.10。

03阶段六：训练循环（八成是老朋友）

循环骨架就是标准 PyTorch 训练循环，唯一的新东西是 stage 4 换成了 GRPO 损失BRM §6.11：

optimizer = torch.optim.AdamW(model.parameters(), lr=1e-5)   # ①
model.train()
for step in range(steps):                                     # ②
    optimizer.zero_grad()                                     # ③
    stats = compute_grpo_loss(model, tokenizer,
                              example=math_data[step % len(math_data)],
                              num_rollouts=4, max_new_tokens=512, ...)  # ④ 新
    stats["loss_tensor"].backward()                           # ⑤
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)   # ⑥ 梯度裁剪
    optimizer.step()                                          # ⑦
    # ⑧ 记录 loss / reward_avg / 平均回答长度 → CSV；每 5 步存 checkpoint
    #    （Ctrl-C 中断也会先存盘再退出）

读训练日志的姿势BRM §6.11：reward_avg=0.5 表示 4 个 rollout 中 2 个对；loss 本身别过度解读——reward_avg=0 的步 loss≈0（零优势），大 loss 只说明组内分化大。要看的是长期趋势：平均奖励升、回答长度变化（R1 论文：训练中回答会自然变长——模型自发学会写中间推理）。

M1 Pro 实跑建议书里这章原生支持 MPS（书即用 MPS 演示）。但 0.6B + 4 rollouts × 512 tokens 在 16GB 内存里很吃紧：先用 num_rollouts=2, max_new_tokens=64 冒烟测试，再逐步加大；OOM 就降这两项。checkpoint 每个 ~1.5GB，勤存盘勤删旧。也可直接下载书作者的预训练 checkpoint 评估（huggingface.co/rasbt/qwen3-from-scratch-grpo-checkpoints）。

04成绩单与边界

模型准确率平均 tokens
base（第 5 课基线）15.2%79
官方 reasoning48.2%1370
GRPO 50 步（256 tok × 4 rollouts）43.2%560
GRPO 50 步（512 × 4）45.6%580
GRPO 50 步（512 × 8）47.4%586

表 1 · MATH-500 全集评估（评估时上限 2048 tokens）。BRM table 6.1

四个读数：

  1. 50 步就够解锁推理行为——但书作者实测：再训下去不涨反跌，原始 GRPO 长跑不稳定（下一课修）。
  2. rollout 数量和 token 上限都换得到准确率：2→4→8 rollouts、256→512 tokens，一路涨。训练时的 token 上限塑造了回答长度习惯——所以平均 580 tokens，远短于官方的 1370。
  3. 上限别卡太死：推理需要空间写中间步骤；R1 的经验是回答会越训越长。
  4. 距离官方只差 0.8 分，而差距主要是训练预算（步数、rollouts、token 上限）。
工作决策框架「我们要不要自己 RL 微调」的判断树：任务可自动验证吗（数学/代码/单测）→ 有 base 权重和算力吗（50 步就能 +30 分是极强的信号）→ 不稳定问题能接受吗（需要下一课的工具）。反过来，如果任务不可验证，别硬上 RLVR——那该走 RLHF 或蒸馏（第 15 课）。

05检索练习

一句话带走 GRPO 损失 = −mean(优势 × 序列 logprob)：优势定方向，logprob 定幅度，梯度只走 logprob 一侧。外面套一个标准 PyTorch 循环——50 步，15.2%→47.4%。
