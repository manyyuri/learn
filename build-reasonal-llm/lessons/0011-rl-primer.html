01RL 在 LLM 流水线里的位置

预训练学"下一个词是什么"（你已经从上一本书掌握）；RL 是 post-training：在预训练（或指令微调）之后，优化整个输出——答案对不对、人喜不喜欢——而不是逐 tokenBRM §6.1。一句话分工：预训练储备知识，RL 塑造知识的用法。

两种 RL 阶段BRM §6.1：推理训练（本课主角，可像 DeepSeek-R1-Zero 那样直接怼在 base 模型上）→ 偏好调优（RLHF，通常在后）。

图 1 · RLHF 两步：奖励模型（本身是个 LLM，学会了模仿人类偏好打分）+ RL 微调。BRM §6.1.1

例：问"买笔记本看什么"，回答 A 罗列全部参数，回答 B 给出具体建议（16GB 内存、SSD…）——标注员普遍偏好 B。成千上万对这样的偏好对，喂给奖励模型；此后 RL 训练时奖励模型自动打分（好答案 +2，差答案 −2），不再麻烦人类BRM §6.1.1。这就是 InstructGPT/ChatGPT 的关键配方（InstructGPT 论文，2022）。

痛点：奖励模型又贵又难训（往往和主模型一样大），且打分带噪声。

03RLVR：把奖励模型换成验证器

RLVR（Reinforcement Learning with Verifiable Rewards）：用一个确定性的验证器替代学的奖励模型——正是你在第 4 课手写的那个数学验证器！答案对且格式合规 → 奖励 1；否则 0。两步流水线坍缩成一步：采样 → 验证打分 → 更新权重BRM §6.1.2。

RLHFRLVR
奖励来源训练出的奖励模型（模仿人）确定性验证器（数学/代码）
管线两步（训 RM + RL）一步
成本高（RM ≈ 主模型规模）低（无额外模型）
稳定性RM 打分有噪声确定、可复现
适用域主观偏好（聊天、文风）仅可验证域（数学、代码）

RLVR 因 DeepSeek-R1（2025）一战成名：不靠人类偏好数据，纯用可验证奖励训出强推理BRM §6.1.2。代码任务的验证 = 沙箱里编译运行（书不展开，因需安全隔离环境；算法与数学版完全相同）。

04RL 黑话 → 你已知的概念

RL 术语在这本书里 =你已在哪里见过
policy 策略就是被训练的那个 LLM—
rollout对一道题生成的一整个回答≈ 第 8 课的一份采样
reward 奖励验证器给 rollout 的分（1/0）第 4 课验证器
logprob当前模型对 rollout 的自信程度第 9 课 logprob 打分
advantage 优势奖励减去同组平均（标准化）≈ 第 8 课"相对多数"直觉
KL 惩罚别偏离原模型太远的缰绳下一章细讲

主厨比喻（书原创，超好用）BRM §6.2.1：你是厨师（policy）；顾客点千层面（prompt）；你按几种不同配方试做（rollouts）；顾客只尝完整成品再评价（reward，不看做菜过程）；对比哪些配方受欢迎（advantage，组内相对）；记录每道菜有多"像你的风格"（logprob）；据此调整烹饪风格（policy gradient 更新）——同时对照老菜谱、避免风格剧变吓跑老顾客（参考模型 + KL 惩罚）。

最易混淆的一对RLVR 决定"学什么信号"（验证器给奖励），GRPO 决定"怎么用信号更新权重"。GRPO 是策略优化算法——PPO 的简化亲戚：PPO 要额外训一个价值模型来估计基线，GRPO 直接用组内相对比较当基线，省掉一个模型BRM §6.2。这就是 "G"（group）的含义。
剧透：这章的威力base 模型 MATH-500 准确率 15.2% → 47.4%，只训 50 步——逼近官方 reasoning 模型的 48.2%BRM table 6.1。接下来两课就是这 50 步的完整解剖。

05检索练习

一句话带走 RLHF = 训练奖励模型模仿人偏好（两步、贵）；RLVR = 确定性验证器直接发奖励（一步、稳，限可验证域）。policy=LLM、rollout=一整条回答、advantage=组内相对好坏。GRPO 用组内比较省掉价值模型。
