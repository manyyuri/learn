第 10 课 · Self-Refinement：让模型批改自己

📖 BRM §5.7–5.8 ⏱ 25–35 分钟 🎯 收获：草稿→批评→修订循环 + 一张诚实的成绩单（打分器可能帮倒忙）

为什么学这个：这是三大推理时方法的最后一个，也是最像人类的一个：先写、再审、再改。它不依赖"可提取的短答案"，适用面比投票广。同时这课有一个珍贵的反面结论：上节课精心搭建的 logprob 打分器，实测里是三个选项中最差的——亲眼看看"听起来合理的方法如何被实验打脸"，正是你工作里评估技术方案最需要的肌肉。

图 1 · self-refinement 一轮。可迭代多轮；打分器可选（不装则永远接受最新版）。BRM fig 5.20/5.21

两个 prompt 模板BRM §5.7, listing 5.10–5.11：

def make_critique_prompt(raw_prompt, draft):
    return ("You are a meticulous reviewer. Identify logical errors, missing "
            "steps, or arithmetic mistakes. If the answer seems correct, "
            "say so briefly. Then propose a concise plan to fix issues.\n\n"
            f"Question:\n{raw_prompt}\n\nDraft answer:\n{draft}\n\n"
            "Write a short critique and bullet-point fix plan (under ~120 words).\nCritique:")

def make_refine_prompt(raw_prompt, draft, critique):
    return ("Revise the answer using the critique. Keep it concise and "
            "end with a final boxed result: \\boxed{ANSWER}\n\n"
            f"Question:\n{raw_prompt}\n\nPrevious answer:\n{draft}\n\n"
            f"Critique:\n{critique}\n\nRevised answer:")

书中实例（T=0.7, p=0.9）：草稿答 \boxed{18}（错，正确 83）→ 批评环节写出五步修正计划（乘 2 消分母 → 移项 → x=83）→ 修订答案 \boxed{83} ✅BRM §5.7

微妙之处那份批评里说"题目本身有逻辑错误"——并不成立，但它附带的修正计划是对的。教训：批评不必全对也能有用，只要它把修订往好的方向推。BRM §5.7

02循环 + 打分裁决

self_refinement_loop 把流程打包成多轮迭代，核心结构BRM §5.8, listing 5.12：

def self_refinement_loop(model, tokenizer, raw_prompt, device,
                         iterations=2, score_fn=None, ...):
    current_full = 生成草稿(...)
    current_score = score_fn(...) if score_fn else 0.0
    for it in range(iterations):
        critique  = 生成(make_critique_prompt(raw_prompt, current_full))
        revised   = 生成(make_refine_prompt(raw_prompt, current_full, critique))
        revised_score = score_fn(...) if score_fn else 0.0
        if revised_score >= current_score:      # 不退步才接受
            current_full, current_score = revised_full, revised_score
    return {"final_full": ..., "steps": [...]}

打分器即插即用——用 functools.partial 把上节课的 avg_logprob_answer 预绑参数做成 score_fnBRM §5.8。书中单题跑两轮：第 1 轮 10→83（分数 −0.855→−0.226 ✅接受）；第 2 轮 83→83 但分数掉到 −1.320 ❌拒绝——打分器防住了"越改越差"。

五个扎心的读数BRM §5.8：

  1. base 模型上 self-refinement 有效但平庸：最好 25.0%（不打分！），远不如投票的 52%。多轮反而掉分（22.0%）——越改越跑偏。
  2. 两个打分器在 base 上都帮倒忙（21.x < 25.0）：它们有时会拒绝正确的修改、接受错误的修改。
  3. avg logprob 最差，reasoning 模型上甚至打回原形（48.4% ≈ 基线）——因为它奖励"模型觉得顺"而非"答案对"，正是第 9 课警告的自信的失误。
  4. reasoning 模型才是 self-refinement 的主场：+9.6 分（48.2→57.8，配启发式打分）。它训练过"检查自己的推理"，更会批评自己。
  5. base + CoT + self-refinement 直接失败（书中未列数）——方法组合不总是叠加增益。
工作决策框架三个推理时方法的选型（数学类任务，base 模型）：CoT（便宜打底）→ self-consistency（上限最高 52%）；self-refinement 更适合已训练的推理模型或无短答案的开放任务。天花板：DeepSeekMath-V2 用「专门训练的批评模型 + 训练主模型配合修正」拿到竞赛金牌级（2025.11）——说明这条路线吃训练，纯 prompt 版收益有限。BRM §5.8

04阶段收官

至此 Stage 3（推理时扩展）完结：CoT、self-consistency、self-refinement 三张牌都会了，也都知道各自的账单和适用面。但它们的共同天花板是——模型本身没变。下一阶段（ch6–7）开始动真格：用强化学习更新权重，把模型本身变成推理模型。BRM §5.8, fig 5.22

05检索练习

一句话带走 Self-refinement = 草稿→批评→修订循环 + 打分门卫（不退步才接受）。base 上不如投票（25% vs 52%）；reasoning 模型上 +9.6 分；logprob 打分器最容易把流畅的错误放行。
