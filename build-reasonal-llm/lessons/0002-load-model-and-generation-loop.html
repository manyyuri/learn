全书用 Qwen3 0.6B base 模型作为实验台BRM §2.5。为什么是它：小而够强、开源权重（open-weight，可下载训练好的权重）、能在消费级硬件上跑；而且 Qwen3 家族同时有 base 版和官方推理版，方便后面做对照。

🚗 大众甲壳虫Raschka 的比喻：学造车不必从法拉利开始——造一辆甲壳虫反而更能看清引擎和变速箱。DeepSeek V3（R1 的底座）训练用了 2048 块 H800 约 11 周、1480 万 GPU 时、约 550 万美元；我们用同一套方法、小一号的模型。BRM §2.3

03Tokenizer：文本 ⇄ token ID

模型不认识文字，只认识整数 ID。Tokenizer 负责双向转换BRM §2.4：

from pathlib import Path
from reasoning_from_scratch.qwen3 import (
    download_qwen3_small, Qwen3Tokenizer)

download_qwen3_small(kind="base", tokenizer_only=True, out_dir="qwen3")
tokenizer = Qwen3Tokenizer(Path("qwen3") / "tokenizer-base.json")

prompt = "Explain large language models."
ids = tokenizer.encode(prompt)      # 文本 → ID 列表
print(tokenizer.decode(ids))        # ID → 文本（round-trip 无损）

for i in ids:
    print(f"{i} --> {tokenizer.decode([i])}")
# 840 --> Ex   20772 --> plain   3460 -->  large
# 4128 -->  language   4119 -->  models   13 --> .

注意 "Explain" 被拆成 Ex + plain 两个 token——这是 BPE（Byte Pair Encoding）子词分词：常见词整存，罕见词拆开存；空格通常并入 token（" large" 带前导空格），帮模型识别词边界。BRM §2.4

词表大小的权衡Qwen3 词表约 15.1 万（GPT-2 约 5 万、Llama 3 约 12.8 万）。词表越大：embedding 和输出层越大、单 token 计算越贵；但更多词能整词成 token → 序列更短 → 总计算反而不一定多。BRM §2.4

04一次前向传播里发生了什么

关键直觉——模型一次算出每个位置的"下一个词"预测，但我们只用最后一个BRM §2.6：

input_tensor = torch.tensor(ids).unsqueeze(0).to(device)  # (1, 6)
with torch.inference_mode():
    out = model(input_tensor)          # (1, 6, 151936)
print(out.shape)  # torch.Size([1, 6, 151936])
6 个输入 token每位置都有输出
→
6 × 151,936 分数矩阵logits
→
只取最后一行[-1]
→
argmax → 下一个 token
图 1 · 6 个 token 进 → 6 行 logits 出 → 只用最后一行（它预测的是"还没出现的下一个词"）。BRM fig 2.11–2.12
  • unsqueeze(0)：把一维 tensor 变成 (1, 6)——模型按批（batch）维度设计。BRM §2.6 侧栏
  • logits 是每个词表项的原始分数（此书权重是 bf16，所以你会看到 dtype=torch.bfloat16）。
  • torch.argmax 取分数最大的位置——位置号恰好就是 token ID。这叫 greedy decoding（贪心解码）：永远选最高分。第 7 课我们会换成带随机性的采样。BRM §2.6 侧栏
  • torch.inference_mode()：推理不记梯度，省内存提速。BRM §2.6

05生成循环：20 行核心代码

把"预测一个 token"套上循环，就是全部的生成机制BRM §2.7, listing 2.2：

@torch.inference_mode()
def generate_text_basic_stream(model, token_ids, max_new_tokens, eos_token_id=None):
    model.eval()                                    # 关掉 dropout 等，确定性
    for _ in range(max_new_tokens):
        out = model(token_ids)[:, -1]               # 只要最后一个位置的 logits
        next_token = torch.argmax(out, dim=-1, keepdim=True)
        if eos_token_id is not None and torch.all(next_token == eos_token_id):
            break                                   # 生成完（EOS）就停
        yield next_token                            # 流式吐出，边生成边打印
        token_ids = torch.cat([token_ids, next_token], dim=1)  # 拼回输入

跑起来（首次会下载 1.4 GB 权重）：

download_qwen3_small(kind="base", tokenizer_only=False, out_dir="qwen3")
model = Qwen3Model(QWEN_CONFIG_06_B)               # 随机初始化的壳
model.load_state_dict(torch.load("qwen3/qwen3-0.6B-base.pth"))  # 装入预训练权重
model.to(device)

for token in generate_text_basic_stream(
        model, input_tensor, max_new_tokens=100,
        eos_token_id=tokenizer.eos_token_id):      # EOS = <|endoftext|>, ID 151643
    print(tokenizer.decode(token.squeeze(0).tolist()), end="", flush=True)

输出（书里的实际结果）：

"Large language models are artificial intelligence systems that can understand, generate, and process human language, enabling them to perform a wide range of tasks, from answering questions to writing articles, and even creating creative content."

注意两个细节：① 第一个 token " Large" 带前导空格是正常的（分词器习惯）；② 不传 eos_token_id 的话，模型在 <|endoftext|> 后会继续写新"文档"停不下来——EOS 是训练时文档结束的标记。BRM §2.7

本课核心书里所有花活都长在这个循环上：第 4 课往里加"取答案"；第 7 课把 argmax 换成温度采样；第 8 课在外面套 16 次循环投票；第 12 课把它变成可训练的 rollout 生成器。生成循环 = 全书的主干线。

06检索练习

一句话带走 生成 = tokenizer 编码 → 循环【前向传播取最后位置 logits → argmax → 拼接】→ EOS 或达上限即停 → 解码回文本。
