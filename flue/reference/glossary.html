术语表（Glossary）

本课程所有课程、参考文档使用的统一译法。英文术语首次出现一律「中文（English）」；标 L 的条目后续课程会补详。术语会随课程推进持续新增。

目录： 核心心智 · hooks 分类 · 机制层 · 接口层 · 地基

A核心心智（Core mental model）

agent 函数（agent function）

代表一个 agent 的普通 JS/TS 函数：返回该 agent 的系统指令（system prompt instructions）文本。在 flue 中「agent 就是函数」，不是配置对象。函数名默认成为 agent 的持久身份（见 agentName）。
guide/building-agents.md · runtime/src/hooks/render.ts

渲染 / 重渲染（render / re-render）

执行一次 agent 函数并收集其声明的过程。函数每个 turn（每次要调用模型前）都会重跑，像 React 组件的 render——返回的指令永远反映当下状态。渲染期间 hooks 把能力落到一个「渲染帧」上。
guide/building-agents.md「re-renders on every turn」· runtime/src/hooks/frame.ts

hook

在 agent 函数体内调用的普通函数，给 agent 加一种能力，名字都以 use 开头（useModel / useTool / useSkill / useSandbox 等）。只能在 render 期间调用。
guide/agent-hooks.md · runtime/src/hooks/*

turn / 提交（submission）

一次「把一条投递消息喂给 agent、直到产出一条回复」的执行单元。提交开始时先做首渲染；每轮模型调用前会重渲染。若干「turn/轮」组成一次 submission（一次被接受的工作，可重放）。
runtime/src/client.ts（submission-scoped）

harness（工具套件层）

模型之外的整套「干活环境」：工具、技能、指令、文件系统/沙箱，以及支撑自主工作的会话与持久化。flue 的核心理念是 harness-first——harness 是框架本体，不是某个功能。构建 agent 的三要素：LLM × harness × 专精上下文。
guide/why-flue.md · guide/building-agents.md

"use agent" 指令（directive）

写在模块顶部的字符串（类似 'use client'）。构建时 flue 扫描带此指令的文件，把每个导出的首字母大写函数注册成 agent。注册 = 可被 dispatch / HTTP 路由寻址。
guide/building-agents.md · packages/vite/src/use-agent-transform.ts

agentName / agent 身份（identity）

函数导出名 = agent 的持久身份，用来键控其在存储里的会话。重命名函数不改数据库时，用静态属性 TriageAgent.agentName = 'triage-agent' 钉住身份。
guide/building-agents.md · guide/reference/agent-api（Agent statics）

agent 实例 / 会话 ID（instance / id）

agent 总以一个 ID 初始化（--id、POST 的 /:id、或 dispatch 的 id），ID 的含义由你定（用户 ID、工单号……）。实例按 ID 持久化，可跨时间继续对话。
guide/building-agents.md

Bhooks 分类（可另见 第 1 课 §3）

useModel / provider / 模型说明符（model specifier）

声明 agent 用的模型，如 'anthropic/claude-sonnet-4-6'。每次 render 恰好调用一次；参数可随状态变化（但调用不能消失）。值是 submission 作用域：提交开始时读取，本次运行中途不变。不带 useModel 的 render 无法开始。
runtime/src/hooks/use-model.ts · guide/models.md

useInstruction

往系统指令里追加一段文字，作为 return 的补充贡献（按调用顺序并入最终指令文档）。
runtime/src/hooks/use-instruction.ts

useTool / 工具（tool / ToolDefinition）

给 agent 一个可调用的动作：名字 + 描述 + 输入 schema（valibot）+ run。工具可在工具内改持久状态、触发解锁其它工具。能力可以条件增减。
runtime/src/hooks/use-tool.ts · guide/tools.md

useSandbox / 沙箱（sandbox）

给 agent 一个文件系统与命令执行环境（本地 local()、虚拟、或远程容器）。标准模型侧工具（bash/edit/read/write/grep/glob…）挂在沙箱的 tools 列表上。
runtime/src/hooks/use-sandbox.ts · runtime/src/agent.ts · guide/sandboxes.md

useSkill / 技能（skill / SKILL.md）

挂载一个 agentskills 格式的 SKILL.md（目录 + frontmatter，name 须等于目录名）。SKILL.md 通过静态 import 挂载（动态 import 是构建错误）。
runtime/src/hooks/use-skill.ts · packages/vite/src/markdown-import-plugin.ts · guide/skills.md

useSubagent / 子代理（subagent / delegate）

让 agent 把专项工作委派给另一个 agent 函数（delegate）。delegate 在父级 useSubagent 定义上声明自己的模型；delegate 渲染是 subagent 帧，不能 usePersistentState / useSandbox（共享父级环境）。
runtime/src/hooks/use-subagent.ts · guide/subagents.md

usePersistentState / 持久状态（persisted state）

签名像 useState，但值持久：每次写入都记录进会话存储，每次 render 读到最新值——跨 turn、跨重启、贯穿整个会话。值须 JSON 可序列化，按 name 键控。用 updater 函数 (prev) => … 而非读渲染快照。
guide/agent-hooks.md「Persisted state」· runtime/src/hooks/use-persistent-state.ts

事件 hooks（event hooks）

在生命周期固定时点注册回调：useResponseStart / useAgentStart（每次收到消息都跑，async，适合加载数据）/ useAgentFinish / useResponseFinish。回调至少执行一次——完成的工作会持久提交、绝不重复，被打断会重试；所以「不能做两次」的事要用持久状态兜底。
guide/agent-hooks.md「Event hooks」

自定义 hook（custom hook）

把若干 use* 声明抽成自己命名的函数（以 use 开头），像 React 那样组合、跨 agent 复用（如一个打包好工具/技能/指令的 useGitHub()）。
guide/agent-hooks.md「Custom hooks」

其余 hooks（L，后补）

useInitialData（读创建时的结构化数据）、useDataWriter（向客户端流式写结构化数据，模型看不见）、useDelivery / useDispatchMessage（读触发消息 / 给本 agent 实例派发）、useMcpConnection（挂 MCP 服务器工具）。
runtime/src/hooks/ · guide/agent-hooks.md

C机制层（Mechanism）

渲染帧（render frame）

模块级的全局 slot——agent 函数运行期间 hooks 对着它解析并落盘（与 Preact 的 currentComponent 同思路）。自定义 hook 只是普通函数，所以它调的 hooks 记录得就像 agent 主体直接调用一样。帧为空时调用 hooks 会抛错。
runtime/src/hooks/frame.ts

持久化/可靠性（durability）

flue 的核心卖点：每个会话都记录到可重放日志，被接受的活绝不丢——中断的会话在运行时回来时自动续上，客户端不从头开始。事件 hooks 的「至少一次 + 完成后不重复」由它保证。agent 静态属性 durability = { maxAttempts, timeoutMs } 配置。
guide/why-flue.md「Durable」· guide/durability.md · runtime/src/agent-execution-store.ts

上下文压缩（compaction）

会话过长时自动把历史压成摘要/精简表示，避免超窗口与成本失控。可经 useModel 的 options 关闭阈值压缩（compaction: false）或调配置。
runtime/src/compaction.ts · runtime/src/hooks/use-model.ts（UseModelOptions）

会话 / 会话存储（conversation / storage）

一次 agent 实例（按 ID）的全部消息与持久状态的记录。默认落在项目配置的数据库（无数据库时用本地缓存文件；CLI 本地默认 SQLite run.db）。可换 Postgres（@flue/postgres）等。
guide/building-agents.md「Conversations persist」· guide/database.md · Headroom 项目（@flue/postgres）

会话投影（conversation projection / events）

运行时可把会话的实时更新（逐块文本、工具事件、数据 parts、元数据）流给订阅者/客户端——SDK 的 observe、HTTP 的 GET 长连接都读这个投影。
runtime/src/conversation-public.ts · packages/sdk/src

派发（dispatch）

当应用异步收到事件（webhook、队列、聊天事件）时，把消息交给某个 agent 会话处理的方式：dispatch(Agent, { id, message }) 立即返回回执、异步处理，不等回复。
guide/building-agents.md · guide/channels.md

D接口层（Interfaces）

flue run（CLI）

本地直接跑一个 agent 模块：不起服务器、不构建应用。对话跨运行持久（本地缓存或配置的数据库）。常用 --id（命名会话以续聊）、--message、--data（initialData JSON）。
guide/building-agents.md · docs/cli/run · packages/cli/src/lib/run-bootstrap.ts

HTTP 挂载（routing / createAgentRouter）

把 agent 挂到你应用的路由里，每个会话有 POST /agents/<name>/<id>：POST 消息即发即收（202 fire-and-forget），GET 同一 URL 读事件流。需用应用自己的中间件保护。
guide/building-agents.md「HTTP」· guide/routing.md

@flue/sdk（客户端 SDK）

围绕一个会话 URL 封装整个读/写面：send() / wait() / observe() / history() 等，消费已部署 agent 的对话。
guide/building-agents.md · packages/sdk/src/public/*

start() / init()（编程入口）

在自己的 Node 进程里直接引导 flue 运行时（start，可给 agents + db，适合 cron/脚本/测试），再用 init(Agent, { id }) 拿实例句柄 dispatch/read。
guide/building-agents.md「Standalone scripts」· runtime/src/agent-client.ts

E地基（Foundation）

Pi / pi.dev（flue 的地基层）

flue 官方明言建在 Pi 之上（OpenClaw 背后的开放 agent harness）。源码证据：@flue/runtime 依赖 @earendil-works/pi-ai 与 @earendil-works/pi-agent-core（同版本 ^0.83.0——正是 stylist 项目直接用的 pi-ai 版本）。flue 复用其 provider/模型层与消息/工具类型，自建 render、会话、durability、HTTP/SDK 与 vite 变换。
guide/why-flue.md「Harness-first」· packages/runtime/package.json · runtime/src/usage.ts / provider-diagnostics.ts / compaction.ts

valibot（输入 schema）

flue 工具输入与 initialData 的类型运行时校验用 valibot（小而快的 schema 库），与 @valibot/to-json-schema 一起生成模型的工具 JSON schema。
packages/runtime/package.json · stylist-agent（valibot 1.0.0）

MCP（Model Context Protocol）

开放协议，把第三方工具/服务以「MCP 服务器」接入 agent（useMcpConnection / defineMcpConnection），接入认证过的外部工具生态。
guide/mcp.md · runtime/src/mcp.ts

Durable Streams

flue 采用的开放流式协议标准（与之相对的不自造协议）。会话事件、回复流都按其语义表达。
guide/why-flue.md「Open」· docs（durable streams 参考页）
