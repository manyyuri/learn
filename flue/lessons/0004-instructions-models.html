指令与模型：useModel 的两条铁律与 provider 解析

读完这一课，你能说清 model specifier 是怎么被解析成一次真实模型调用的、中途换模型为什么"下个 submission 才生效"，以及 compaction/thinking 是挂在谁的绳上。

§0开场检索

§1useModel 的两条铁律

每个 agent 同一时刻被恰好一个 LLM 驱动，用 useModel() 声明。它是 agent 里唯一必须的 hook，两条规则：

  • 必须调用：不带 useModel 的 render 无法开始。
  • 每次 render 恰好一次：参数可以逐 render 变化（从持久状态里挑模型），但调用不能消失、不能重复——帧上已有 model 再调就抛 "called twice in one render"。

它是声明不是客户端：什么都不返回，你从不 new SDK 对象、从不把 API key 穿过 agent 代码——连接、鉴权、流式、重试全归运行时。
runtime/src/hooks/use-model.ts（校验）· guide/models.md（Declaring a model）

§2model specifier 与 provider 解析

模型说明符是 'provider-id/model-id' 的字符串，第一个 / 前是 provider，后面是 provider 自己的模型 id（可能还含 /）：

  • anthropic/claude-sonnet-4-6 → provider anthropic
  • openrouter/moonshotai/kimi-k2.6 → provider openrouter、模型 moonshotai/kimi-k2.6
  • cloudflare/@cf/moonshotai/kimi-k2.6 → provider cloudflare（Workers AI 目标）

默认解析用 pi 的内置 provider 全集（anthropic/openai/google/groq/mistral/xai/deepseek/cerebras/together/fireworks/openrouter…）。每个 catalog 条目带模型元数据：wire 协议、endpoint、上下文窗口、输出上限、成本、是否支持 reasoning/图片——compaction 阈值、thinking 是否上 wire、能不能收图都由它决定。

只想带用到的 provider，就在 flue() 插件配置里列 providers: ['anthropic','openai']——生成的服务入口只 import 这些工厂。列表是穷尽式的：没列到的 provider，specifier 直接解析失败。
guide/models.md（Model specifier / providers config）

未知 specifier fail fast：请求发出前就报「unresolved provider + model id」。这也解释了 flue skill 红线的实战来源——provider 没配密钥时那句 Provider is not configured 就是在这层抛的。

§3submission 作用域：为什么换模型要等下一提交

model、thinkingLevel、compaction 都是 submission 作用域：运行时在 agent「醒来处理一个被接受的输入」时读一次。中途重渲染算出的新值会「锁存」，但只作用于下一次 submission——不会在当次进行到一半时换。

典型升级（escalation）模式：

const [escalated, setEscalated] = usePersistentState('escalated', false);
useModel(escalated ? 'anthropic/claude-opus-4-6' : 'anthropic/claude-haiku-4-5');

点了 escalate_review 的那次响应仍跑在便宜模型上；对话的下一条消息才切到强模型。注意 dispatch/HTTP 层没有 per-message 模型参数——模型选择属于 agent 函数。
guide/models.md（Changing models mid-conversation）· runtime/src/hooks/use-model.ts（submission-scoped）

§4调优两个旋钮：thinkingLevel 与 compaction

useModel(model, options) 的 options 只有两个字段：

  • thinkingLevel：'off'|'minimal'|'low'|'medium'|'high'|'xhigh'|'max'，默认 'medium'；只是默认值——subagent 定义、harness.prompt 可逐操作覆盖。只有 catalog 标记 reasoning-capable 的模型，thinking 才会真上 wire（自定义 provider 若跳过 reasoning 元数据，会被静默丢弃）。
  • compaction：临近上下文上限时自动把旧历史折叠成摘要、保留近期原文。可调 reserveTokens（提前多少触发，默认 model-aware ≤20000）、keepRecentTokens（多少近期原样存活，默认 8000）、model（用便宜模型做摘要）。compaction:false 只关阈值压缩，溢出恢复和显式 harness.compact() 仍会压。
guide/models.md（Model reasoning effort / Compaction）· runtime/src/agent-tuning.ts

§5凭证从哪来：环境，不是你的代码

  • 本地：项目根 .env（ANTHROPIC_API_KEY 等）；flue run 自动加载（--env 换文件）；vite dev 按 vite 那套 .env*。shell 导出的值永远压过文件值。别把 .env 提交。
  • 部署态：Node 读进程环境变量（宿主 secrets 机制）；Cloudflare 用 wrangler secret put，本地用 .dev.vars。
  • 自定义：provider 的 auth.apiKey.resolve() 返回你代码产出的任何凭证——网关 key、secret manager 都行，每次请求都跑，轮换也支持。
guide/models.md（Provider credentials）

§6useInstruction 与 response 元数据：补丁式组装

  • useInstruction(text)：低层逃生舱——把一段原样文本追加到「return 指令之后、按调用顺序」。无结构、无身份、无变更追踪，零散拼接可用，成体系的东西应抽自定义 hook。
    runtime/src/hooks/use-instruction.ts
  • useResponseStart/Finish 的返回值：深合并到响应的 metadata（AI SDK 惯例，信封字段，客户端在内容流之外读）——打时间戳、记 token 就靠它：useResponseFinish(({metadata,response}) => ({ elapsed, totalTokens: response.usage.totalTokens }))。
    guide/agent-hooks.md（Event hooks）· runtime/src/hooks/use-response-start.ts

§7本课自测

本课的胜利：model 的声明与解析链路一句话讲清——你给 useModel('provider/model')，运行时按 provider 表解析出元数据、按环境取凭证，在每个 submission 开始时把「模型 + thinking + compaction」钉成当次的调用配置。
