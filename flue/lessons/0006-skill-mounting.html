skill 挂载机制：为什么 SKILL.md 必须静态导入

读完这一课，你能讲清 skill 从「目录 + SKILL.md」到「打包进 bundle → 一行目录条目 → activate_skill 激活」的整条链路，以及为什么它和你的 pi skills 能互通。

§0开场检索

§1三件套与渐进披露

skill 打包「可复用专长」：工具执行代码，skill 教流程。每个 skill 三部分——name（模型激活用的短 id）、description（一两句：干什么 + 何时用；这是模型唯一一直看到的部分，承载全部路由决策）、instructions（完整流程，激活才加载）。可带支持文件（checklist/模板/参考），显式读取前不加载。

核心设计是渐进披露（progressive disclosure）：每个挂载的 skill 只花系统提示里一行常驻目录条目（name+description），模型判定任务匹配才激活、拿全量 instructions、按需读支持文件——一个 agent 挂几十个 skill 也不必每轮为内容付费。
guide/skills.md（What is a skill）

§2frontmatter 校验

导入或被发现的每个 SKILL.md 都按 Agent Skills 规范校验：name（必填：小写字母数字连字符、≤64、必须等于目录名）、description（必填 ≤1024）、其余字段可选且大多只记录（license/compatibility/metadata/allowed-tools）。未知字段忽略，所以带宿主自定义字段的 skill 照样能载。
guide/skills.md（Frontmatter fields）· runtime/src/skill-package.ts

§3import 即声明：打包层在干嘛

按模块说明符 import SKILL.md：构建时 vite 的 markdown-import 插件识别、校验 frontmatter、把整个目录打进应用 bundle。import 的值是类型化的 SkillReference，交给 useSkill(ref)。npm 包发布 SKILL.md 子路径也能 import。

import refunds from '../skills/refunds/SKILL.md';
export function SupportAgent() {
  useModel('anthropic/claude-haiku-4-5');
  useSkill(refunds);
  return 'Answer customer support questions clearly and accurately.';
}

没有注册步骤、没有运行时文件拷贝——import 本身就是声明，dev / vite build / flue run 三处一致。几条规则：

  • 必须静态：动态 import('./skills/x/SKILL.md') 是构建错误（打包期要知道目录内容）。
  • 同名一次 render 一次：重复挂同名字抛错。
  • 打包纪律：跳过 node_modules/.git/dist 等仓库噪音；>1MB 警告；拒包 secrets（.env、私钥、凭证库、符号链接 = hard error）。

§4激活机制：为什么是工具调用而非改 prompt

挂载的技能出现在系统提示的 Available Skills 段（每行 name+description）；运行时另给一个 activate_skill 工具。模型判定任务匹配 → 调工具传技能名 → 完整 instructions 作为工具结果返回。

因为 instructions 走工具结果而不是进系统提示：技能激活不改变 prompt 前缀，provider 的缓存前缀存活。激活未知名不是错误——结果会列出可用技能。你的指令也能引导激活：「Activate the refunds skill before handling any refund request.」
guide/skills.md（How activation works）

§5defineSkill：内容短/生成时的内联姿势

内容短、由数据拼成、或不想建目录时，用 defineSkill({ name, description, instructions, files? }) 在代码里声明——等价于一个技能目录，首次需要时 runtime 打包成与 SKILL.md import 相同形状（自己写规范 frontmatter）。裸 .md import 只当纯字符串（不打包），想当 skill 就塞给 defineSkill 的 instructions。
guide/skills.md（Inline skills with defineSkill）

§6支持文件在运行时

打包技能的支持文件旅行在应用 bundle 里，不进 agent 工作区：运行时在虚拟只读路径提供每个文件（read_skill_resource 工具 + 文件工具的透明解析），激活简报会列出每份资源的确切路径。同一份 bundle 在笔记本 / Node / Cloudflare 上给同一批文件——无每环境文件系统配置，agent 也永远改不到自己的技能内容。
guide/skills.md（Supporting files at runtime）

§7workspace skills：另一条发现路径

带沙箱的 agent 在会话启动时扫沙箱工作目录的 .agents/skills/，每个合法 <name>/SKILL.md 自动进目录——无 import、无 useSkill。与 declared skill 的差别：内容激活时从磁盘实时读（会话中改立即可见）、支持文件就是普通工作区文件、坏格式只警告跳过（import 的在构建期严格校验、报错可行动）。工作区技能撞 declared skill 名 = 错误。

选择：workspace skills 用于专长跟着工作区走（仓库 checkout、CI、预设运行时工作区，让任何 agent 进来就懂它的约定）；declared skills 用于专长属于你的应用。
guide/skills.md（Workspace skills）

§8为什么你的 pi skills 能直接搬

flue skill 就是 agentskills.io 格式（目录 + SKILL.md，frontmatter 的 name 必须等于目录名）。同一份规范被 pi / flue 等 harness 共用——所以你 ~/.pi/agent/skills 里的技能目录（金融、营销、novel 系列……）只要目录名 = frontmatter name，拷进 src/skills/（或 agents/skills/）静态 import 挂 useSkill 就能复用。Headroom 就这么放：agents/skills/{energy-management,communication,safety}/SKILL.md，中文指令、规范格式。你在 pi 侧沉淀的专长，等于 flue 侧的可移植资产。
guide/skills.md（Follow the open Agent Skills format）· Headroom 项目（agents/skills/*）· flue skill（实测：pi skill 目录可直接复用）

§9本课自测

本课的胜利：skill 的一生——目录/SKILL.md（agentskills 格式）→ 构建期静态打包（import 即声明）→ 常驻一行目录 + activate_skill 按需取 instructions → 支持文件 bundle 内虚拟只读。你 pi 侧的技能目录因此可零改造搬进 flue。
