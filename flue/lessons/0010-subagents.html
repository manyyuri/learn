subagents 与委派：干净上下文里的专注工作

读完这一课，你能讲清委派的三步机制、delegate 继承什么/隔离什么、为什么委派深度封顶 4 层——以及工具/技能/子代理三种原语何时选谁。

§0开场检索

§1声明：useSubagent 三要素

委派对象叫 subagent——一个命名的 delegate，agent 可把专项工作交给它。定义三个必填字段：name、description、agent 函数。description 是父模型决定要不要委派时读的那行——像写好的工具描述一样写清楚「干什么 + 何时用」。

function Summarizer() {
  return 'You summarize support cases in three sentences.';
}
export function CaseAgent() {
  useModel('anthropic/claude-sonnet-4-6');
  useSubagent({ name: 'summarizer', description: 'Summarizes one support case.', agent: Summarizer });
  return 'Investigate the case. Delegate the summary to the `summarizer` subagent.';
}

关键：Summarizer 故意不 export。delegate 的 agent 函数不是已注册 agent——没有 useModel、没有会话 id、没有 HTTP 面，只作为挂载它的 agent 的一种能力存在（构建会注册每个 exported 大写函数为顶层 agent）。delegate 可条件挂载；同名两个在一个 render 里挂 = 抛错。

§2委派三步：task 工具驱动

委派是模型驱动的。每个 agent 工具集都含框架自有的 task 工具；声明的 delegate 按 name+description 进系统提示的 Available Agents 段。模型判断合适 → 调 task（delegate 名 + 一段 prompt）：

  1. runtime 在委派时、独立帧里渲染 delegate 的 agent 函数 → 得子代理的指令/工具/技能。
  2. 子代理作为detached 会话在父环境里跑：读任务 prompt、用自己上下文窗口、跑完。
  3. 只有子代理的最终消息作为 task 工具结果回父——中间推理、工具调用、读文件统统不进父会话。

task 工具永远在，但它的 agent 参数只解析已声明的 delegate——没挂 useSubagent 的 agent 没有合法值可传，委派不了。可传可选 cwd 把子代理指到别的目录、可按 attachment id 转发图。
guide/subagents.md（How delegation works）

两个推论要刻进去：①prompt 就是全部简报——子代理看不到父会话，任务 prompt 必须自包含；②task 并行——一个批里的工具调用并行执行，五个独立检查 = 五个并发子会话，各占各的窗口。

§3继承什么、隔离什么

delegate 默认与父隔离，只继承父的环境：沙箱与 harness 工具、工作区上下文（AGENTS.md / workspace skills）、父的模型与 reasoning（可覆盖）。不继承父的对话：历史、指令、工具、技能、子代理、持久状态、initialData 全不继承。

父子的右侧世界只来自 delegate 自己的 render。因为共享沙箱，文件是天然交接面：Reproducer 写 report.md，父在 task 返回后读。delegate 渲染里 useTool/useSkill/useInstruction/自定义 hook/嵌套 useSubagent 照常；实例作用域 hooks 抛错：usePersistentState()、useSandbox()、useModel()，以及客户端向的 useDataWriter / 事件 hooks / useDispatchMessage。

两个覆盖字段：model（delegate 的模型，省略继承父）、thinkingLevel。delegate 换便宜模型是常见模式——每票都跑的归类步骤不需要父的模型。

§4委派深度、持久与内置 GeneralSubagent

  • 嵌套与深度：delegate 可再声明自己的 delegate（嵌套 useSubagent），runtime 封顶 4 层委派深度。
  • 崩溃恢复：子会话写自己的持久记录，任务被打断/重部署从断处续——恢复时重挂到子转录续跑（第 9 课 §5）。
  • GeneralSubagent：flue 内置的空白 delegate，挂在保留名 flue-general 下。agent 函数故意空——子代理只有共享环境（沙箱工具、工作区上下文、父模型），无自己的指令/工具/技能，一切靠任务 prompt 简报。它也是 opt-in：想让它能 fan out 就显式挂。
  • defineSubagent：像 defineTool/defineSkill——在普通模块里定义一次并 export 共享，模块加载时校验（而非首 render），返回冻结对象；挂载时 per-mount 覆盖干净铺开（如给高频 agent 的 classifier 配小模型）。
guide/subagents.md（The general-purpose delegate / Share a subagent）

§5工具 vs 技能 vs 子代理：选型

subagent 最有用时：探索性工作会淹没父上下文但产出很短（研究/代码库探索/日志分析）；工作流某阶段要不同的指令/工具/技能；独立工作可并行各占窗口；某类活要不同模型。对照邻居：

  • 工具：你应用代码执行的有界函数——工作确定性、非模型驱动时用它。
  • 技能：给当前 agent 加指令与资源——需要指导而非隔离时用它。
  • 子代理 ≠ 第二个注册 agent：无会话 id、无持久状态、无地址。想让系统的另一方长期给一个 agent 发消息——注册真 agent 用 dispatch。
guide/subagents.md（When to use a subagent）

§6本课自测

本课的胜利：委派 = task 工具（常驻）+ delegate 名 → 独立帧渲染子代理 → detached 会话跑 → 最终消息回父。记住「prompt 即简报、并行任务、4 层深度、继承环境隔离对话」这五句话，就能设计出干净的 fan-out。
