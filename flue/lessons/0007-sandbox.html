sandbox：attach 一个环境，一次定义四样能力

读完这一课，你能在 virtual / local / remote 三种环境之间做对选择，并说清 useSandbox 的「presence 翻转只在 turn 边界」为什么是关键语义。

§0开场检索

§1attach 一个环境 = 一次定义四样东西

agent 至多一个环境，attach 它一次解锁四件事：

  • 文件与 shell 工具：工具集新增 read/write/edit/bash/grep/glob，全部操作该环境。
  • 工作区上下文：初始化时 runtime 扫工作目录，把 cwd 路径、目录列表、AGENTS.md 内容拼进系统提示。
  • workspace skills：<cwd>/.agents/skills/ 下技能自动入目录（上一课）。
  • 子代理共享：delegate 用同一个环境——task 可换子目录，换不了沙箱。harness 工具也能摸到同一环境。

没 sandbox 就一样都没有：无文件/shell 工具、提示里无工作区、harness.sandbox 抛错；其余（自定义工具/技能/子代理/状态）不受影响。原则：选支持任务的最窄环境。
guide/sandboxes.md（What a sandbox adds）

§2virtual 内存沙箱：最轻、隔离、易逝

纯 TypeScript 实现（just-bash 引擎）：内存文件系统 + 模拟 bash。标准 unix 工具箱大多能用（ls/sed/awk/jq/sort/管道/重定向），还有 curl；从不真的 spawn 进程。

useSandbox(bash(() => new Bash({ fs: new InMemoryFs(), network: { allowedUrlPrefixes: [...] } })));
  • 隔离宿主：命令在进程内模拟，摸不到宿主文件系统/进程/环境变量；网络 opt-in（network.allowedUrlPrefixes 或 dangerouslyAllowFullInternetAccess）。
  • 易逝：每次运行时为新一轮工作从零重建——处理一条消息写的文件下条就没了。要留的知识进持久状态；文件要留就上真沙箱。
  • 够用场景：curl+jq 数据活、文本整形、只要草稿空间的活。harness 工具可 staging 进出同一环境。
guide/sandboxes.md（The virtual sandbox）· runtime/src/sandbox.ts

§3local()：真机绑定，无隔离

Node 目标的内置 local() 把 agent 直接绑到宿主：文件操作走真文件系统，bash 走宿主 shell 真进程。按设计无隔离——适合开发工具、CI、coding agent、自托管自动化；别当不可信请求/多租户的隔离边界。

  • cwd 默认 process.cwd()，local({ cwd }) 覆盖。
  • shell 不继承你的进程环境：默认只放行少量 shell 必需白名单（PATH/HOME/USER/LANG/TERM/TMPDIR 之类），永不带 API key/token/云凭证；其它要 env 逐变量 opt-in（GH_TOKEN: process.env.GH_TOKEN）。给 undefined 可去掉某个默认。env:{...process.env} = 把整个宿主环境（含 secrets）给模型的 shell，只在完全可信环境做。环境在构造时快照一次。
宽 shell 之前先想：特权动作能否做成窄应用工具？模型驱动的 shell 应该持有越少越好——工具里闭包钉死 token，比 shell 里裸奔强。
guide/sandboxes.md（The local sandbox）· guide/node-target.md（local() reference）

§4remote sandbox：按实例给持久工位

要 per-conversation 隔离、完整 Linux 工具链、或不想跑在自己宿主的代码时，装一个 sandbox 适配器（flue add sandbox <provider>；Daytona/E2B/Modal/Cloudflare Sandbox 等）。适配器刻意薄：你的应用创建/复用/删除 provider 沙箱，flue 只连你给的、从不销毁 provider 基建。

useSandbox({
  async createSandbox(options) {
    const client = new Daytona();
    const sandbox = await client.create();
    return daytona(sandbox).createSandbox(options);
  },
});

createSandbox({ id }) 收到 agent 实例 id——工厂先按 id 查已有沙箱再创建，就给每个会话一个跨消息、跨进程重启存活的持久工作区。取消语义：local() 用进程组 kill 真停；多数 provider SDK 无中途取消，reject 后远端命令在后台继续、输出被丢弃。
guide/sandboxes.md（Remote sandboxes）

§5沙箱自带工具 vs 替换默认集

沙箱工厂可带 tools 函数——在时替换框架默认的模型侧工具集（无 exec 环境的适配器会保留 read/write/edit、把 shell 型 bash/grep/glob 换成自己的 executor）。适配器用导出的逐工具工厂（createReadTool/createBashTool…）组合，而不是从零写。
guide/sandboxes.md（Sandbox-provided tools）· runtime/src/agent.ts

§6条件 attach：presence 是唯一可观察量

useSandbox 可条件调用——agent 中途获得/失去沙箱：if (investigating) useSandbox(local({cwd}))。关键语义：

  • presence 在初始化与每个 turn 边界读；翻转时在下个模型调用前换环境——attach 解析声明的工厂，detach 连文件/shell 工具一起摘掉，两边都不带东西过界。
  • 翻转通过单条 environment 信号告知模型（重述当前完整状态 + 警告旧环境文件可能不可达）。系统提示冻结到下次 compaction。
  • 换环境重写 tools 数组 → prompt cache 失效。工厂每次 render 都是新对象，所以「A 换 B 但保持 attach」不会中途换——下个 submission 初始化才生效。条件住在持久状态里，所以可重放：每次后续提交重挂同一声明，按实例 id 键控的适配器解析回同一工位。
guide/sandboxes.md（Conditional attachment）· runtime/src/hooks/render.ts（sandbox presence）

§7本课自测

本课的胜利：选型一句话——要隔离+轻 → virtual；要动真机/仓库/CI → local（信得过环境）；要隔离+持久工位 → remote 适配器按实例 id 键控。无论哪种，「presence 翻转只在 turn 边界」决定了你什么时候能安全地给 agent 增删环境。
