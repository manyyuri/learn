会话与状态：append-only 流里的三种记录

读完这一课，你能说清会话数据库到底存了什么、usePersistentState 为什么靠"record log"就能跨重启存活、以及 Headroom 的 Postgres 选型到底在买什么。

§0开场检索

§1会话数据库存什么（和不存什么）

flue 的数据库存 运行时自己的持久状态，不是你的业务数据。三类记录：

记录内容谁读它
canonical conversations每个会话一条append-only 流：用户消息、助手输出、工具调用与结果、compaction、恢复事实后续每 turn、每个重连客户端、每次崩溃恢复都靠读回它重建画面——单一真相源
accepted submissions受理的输入 + 谁在处理它的 claims/leases受理即持久，中断后可恢复而不是静默丢
persisted state每条 usePersistentState 写入状态跨重启活到会话结束

附件 payload（图等）以不可变记录存在流旁，被流引用。数据库不管：沙箱文件与依赖、外部 API 副作用、provider 凭证、你的业务数据。可持久数据库 ≠ 可持久沙箱，可持久工作区也不保会话史。
guide/database.md（What Flue stores）· guide/durability.md

§2为什么是 append-only 流 + 投影

把对话设计成「只追加的记录流」而非「可变状态表」，换来三件事：

  • 重放即重建：崩溃后没有任何"半写坏"的会话——读回流就能收敛到一致画面；客户端重连也从流重建。
  • 审计可追溯：每个 turn 的每条记录都在，工具调用结果、恢复事实不丢。
  • 投影给客户端：运行时的 conversation-*（reader/projections/public）把流减成客户端事件流——逐块文本、工具事件、数据 parts、元数据实时推出（SDK 的 observe、HTTP 长连接读的就是它）。
runtime/src/conversation-reader.ts / conversation-projections.ts / conversation-public.ts · guide/database.md

§3usePersistentState 的真相：record log 上的 API

源码注释说得直白：它是agent 实例 record log 之上的 API——每条写入都是一条 state_write 记录进 canonical 流，这正是状态能跨重启活到会话结束的原因。

  • 读是渲染快照：本渲染把实例的 state_write 记录 reduce 成当前值。同一渲染内两次读到的旧值，想基于最新写就用 updater 函数。
  • 写是静默的：不 post 消息、不 wake agent、不中途重渲染——下个 turn 的渲染读最新。
  • 写入与「做出它的那单位工作」原子提交：工具里的写入跟那个 turn 的工具批一起提交；若该批被恢复判为中断，写入=没发生。这正是它当 at-least-once 守卫的原因：sent 标志不会在它守卫的邮件回滚后还是 true。
  • 值须 JSON 可序列化；按 name 键控；声明可条件化（缺席只是没碰，不违规）。

§4存储选型：从内存默认到 Postgres

情形行为
无 db.ts（内存 SQLite 默认）一切正常但重启全丢——只够开发/一次性 agent
vite dev缓存文件 node_modules/.cache/flue/dev.db——代码重载不丢，dev server 冷启动重置
flue run缓存文件 node_modules/.cache/flue/run.db——永不重置，所以 --id 能跨调用续对话
sqlite('./data/flue.db')内置 node:sqlite，WAL 模式，单宿主跨重启存活
生态适配器postgres/libsql/mysql/mongo/redis 等，bring-your-own-driver
Cloudflare无需配置——每个会话是 Durable Object + 自带 SQLite（有 db.ts 直接构建报错）
guide/database.md（The in-memory default / sqlite() / Choosing a database）

§5db.ts：按约定的入口模块

源目录（.flue/ → src/ → 项目根）放 db.ts 默认导出适配器即可——vite dev/build、flue run 都按约定解析并启动时连接。适配器是普通 TS，可从环境读连接串、建驱动池。启动时先 migrate()（幂等建表/验表、盖格式版本——不兼容版本的库拒绝启动而非损坏），再 connect()——数据库不可达会在启动时失败，而不是第一次对话中途。start() 脚本不走构建、不吃 db.ts——直接传 adapter 给 db 选项。
guide/database.md（The db.ts entry module）

§6Headroom 复盘：Postgres 在买什么

Headroom 用 @flue/postgres，driver 自己用 pg Pool 包：适配器实现 flue 存储契约，但从不替你挑/绑/配 driver——你给它 query/transaction/close 三个函数，保留对驱动、池化、TLS、凭证的完全控制。blueprint（flue add database postgres）会生成完整 db.ts。

买到的能力：状态在宿主机损失/多 replica 下仍活、替换进程能恢复 accepted work。买不到的：active-active 扩展——共享库让"替换进程"恢复，但每个会话同一时刻仍要恰好一个 Node owner，多副本要把每个会话路由到单一 owner。
guide/database.md（Ecosystem adapters / Choosing a database）· Headroom 项目（@flue/postgres + pg）

§7本课自测

本课的胜利：会话 = append-only 流（三类记录）；状态 = 流里的 state_write；「存储选型 = 换 db.ts 适配器」三句话能讲清。选型买的是「宿主/副本挂了还能恢复」，买不到并发双活。
