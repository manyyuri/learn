render 模型拆解：一次 render 到底发生了什么

读完这一课，你能沿着调用链说清「agent 函数 → 'use agent' 打包 → 渲染帧 → 调用配置」——render 不是魔法，是一条普通函数调用。

§0开场检索：上一课还立着吗

§1从函数到 agent：'use agent' 打包

你在 agents/headroom.ts 里写 'use agent' + export function Headroom()——构建时会发生三件事：

  1. 扫描：vite 插件扫到带指令的模块，把每个导出的首字母大写函数登记为 agent。
  2. 变换：@flue/vite 的 use-agent-transform 给模块追加一行，对每个 agent 调用 __flueBindAgentModule(agentFn, { identity })。
  3. 绑定时机：绑定在模块求值期执行——所以 app.ts 能边求值边 createAgentRouter(agent)；identity 作为构建期字符串字面量打进产物，压缩混淆后身份也不丢。
vite/src/use-agent-transform.ts（append 一个 self-import + 逐 agent 绑定调用）· guide/building-agents.md（'use agent' Directive）
identity 与函数名解耦的意义，正是 Headroom 里 agentName 在做的事：改名不迁移数据库。第 11 课（运行时接口）会看到 agentName 对应到哪一步。

§2一次 render 的内部：一条同步调用

运行时真正执行渲染的代码只有一行——把 agent 函数放进「新帧」里调用：

const { result, frame } = renderWithFrame(() => agent(props), state);

由此可推出四条硬性约束（源码里都有显式断言）：

  • props = { id }：运行时把实例 id 作为 props 传入；无实例支撑的裸渲染（测试/工具）里读 props.id 会抛错。
  • 函数必须同步：返回 Promise 直接报错——「async 工作移到工具、动作或资源工厂里」，不要在 agent 函数体 await。
  • 返回值只能是 string 或 undefined：其它一切（模型、沙箱、工具）都靠函数体里的 hooks 组合。
  • 执行后校验：指令合法性 + 工具名唯一（重复、或撞框架保留名 task/activate_skill 都抛 ToolNameConflictError）。
runtime/src/hooks/render.ts（renderAgentFunctionWithStructure）· runtime/src/hooks/frame.ts

§3hook 凭什么"注册"：渲染帧（render frame）

帧是模块级全局 slot——agent 函数运行的这段时间里，hooks 对着它解析并落盘。frame.ts 明说这是「与 Preact 的 currentComponent 同一纪律」：agent 函数是同步的，单 slot 永不交错；帧为空（在工具/事件/模块作用域里调 hook）就抛错。

所有注册按调用顺序扁平落帧：自定义 hook 只是普通函数，所以 useEscalation() 里调的 hooks，记录得就像 agent 主体直接调用一样。帧上收集的东西就是渲染的「原料」：model、instructions 追加、tools、skills、subagents、mcpConnections、sandbox、cwd、thinkingLevel、compaction、stateNames、messageDataNames、四组事件回调……
runtime/src/hooks/frame.ts（requireRenderFrame 纪律）· guide/agent-hooks.md（Custom hooks）

§4渲染的产物：调用配置 + 结构指纹

渲染完，runtime 把帧映射成两样东西：

① 调用配置（AgentRuntimeConfig）——给「这一轮模型调用」用的一份配置：模型、组装好的指令、工具集、沙箱、技能、子代理、MCP、thinking/compaction。指令文档的拼法有定式：函数 return 的指令在前，useInstruction 的贡献按调用顺序在后，空行拼接（runtime 只负责 join，格式你负责）。
runtime/src/hooks/render.ts（config 组装 + composeAgentDocument）

② 结构指纹（AgentRenderStructure）——跨 turn 比较用，决定「什么变了要告诉模型、什么变了是身份违规」：

声明类别可变性机制
messageDataNames（useDataWriter 的名字）不可变响应客户端身份，两 turn 不一致 = 抛错
resources（tools/skills/subagents）动态会话 diff 前后快照，把增删改「旁白」给模型
usePersistentState 的名字条件友好存储按 name 键控，缺席只是没碰
事件 hooks（use*Start/Finish）条件自由每轮渲染声明什么就跑什么，不指纹
sandbox仅看「在不在」presence 翻转在 turn 边界换环境，绝不中途换
runtime/src/hooks/render.ts（AgentRenderStructure + assertRenderStructureInvariance）

§5"每轮重渲染"到底意味着什么

0001 的地图说「每次调用模型前重跑函数」——现在你能说清后果了：

  • 指令永远新鲜：函数内插了持久状态/时间/数据，每次重跑都重建，模型看到的是当下状态（代价：动态内容会打爆 provider 的 prompt cache，生产上要克制）。
  • 工具集是"每轮从零声明"：工具存在与否只是普通程序逻辑——if (approved) useTool(publish)，没挂载的工具模型根本调不到，比"指令里说不许用"强得多。
  • 变化由会话旁白：工具集/技能增删时，运行时在下个 turn 边界给模型一条 resources 信号（"新工具可用：…"），让转录保持自洽。
  • 换了也是"下个 submission 才生效"：模型/tooling/compaction 是 submission 作用域——中途重渲染算出的新值，锁存到下一次提交才生效。
guide/tools.md（Conditional tools）· guide/agent-hooks.md（re-renders on every model call）· runtime/src/hooks/use-model.ts（submission-scoped）

§6本课自测

本课的胜利：现在你能回答「render 不是魔法，为什么不是」——它是 runtime 把 agent 函数放进帧里的一次同步调用，产物是一份调用配置 + 一份结构指纹，后者决定了哪些变化会被旁白、哪些变化是违规。
