工具系统：模型决定何时，你的代码决定何事

读完这一课，你能讲清一次工具调用的完整生命周期——从模型看到的 schema，到 run 的返回信封，到 harness/durable/条件工具三种变体分别解决什么问题。

§0开场检索

§1工具 = 函数，但由模型调度

工具是你写的函数，写给模型看：模型决定何时调，你的代码决定发生什么。与 skill（教流程）、sandbox（给文件/命令）并列：工具执行你应用的代码。

定义有四个部分：name（模型调用它的名字）、description（教模型何时用——模型唯一的文档）、可选 input（参数 schema）、run（你的代码）。defineTool(...) 校验后返回冻结对象——适合放 src/tools/ 共享；一次性用途直接 useTool({...}) 内联。

import { defineTool } from '@flue/runtime';
import * as v from 'valibot';
export const lookupOrder = defineTool({
  name: 'lookup_order',
  description: 'Look up one order by id and return its current status.',
  input: v.object({ orderId: v.string() }),
  async run({ data }) {
    const order = await orders.get(data.orderId);
    return { output: { status: order.status, eta: order.eta } };
  },
});

§2一次工具调用的生命周期

模型读到 name+description+schemainput 被转成 JSON Schema；无 input 则空对象
↓ 模型带参数调用
valibot 解析参数顶层必须是 object schema
↓ 解析成功
run({ data, signal, log, toolCallId })data 已类型化；校验失败则 run 不被调用，错误回给模型纠正重试
↓ 返回信封
结果回给模型{ output?, terminate? }；裸字符串 = {output} 简写；run 抛错 = 错误结果而非崩溃

几个值得记死的语义：

  • 输入在 run 之前解析：input 必须是 valibot 顶层 object；校验失败 run 永不执行，失败作为工具错误回给模型，让它可以纠正参数重试。
  • 输出是信封：{ output?, terminate? }。output 是要 JSON 化的数据；裸 string 是 {output} 的简写；只有没声明 output schema 时才允许什么都不返回。可选 output schema 做返回校验。想要结束本轮就 terminate:true。
  • run 抛错不崩 agent：变成模型能看到的错误结果，让它换路子或如实告知。
  • context：signal（取消；run 忽略 signal 也卡不死 agent——runtime 放弃 await）、log（长任务进度，流入会话事件，模型看不见）、toolCallId（与调用事件关联副作用）。

§4harness 工具：摸回运行时自己

普通工具是输入的纯函数；声明 harness:true，run 就能拿到 harness：

  • harness.sandbox——agent 的活环境（readFile/writeFile/exec…），直接摸、无会话记录。agent 没声明沙箱就抛错。
  • harness.prompt(text, opts)——在 harness 自己的「草稿会话」里跑一次模型操作；重复调用会续接。可 result（valibot，要结构化结果）或 tools（仅那次操作的额外工具）。

典型：一个工具调用里 staging 文件 → 聚焦模型工作 → 校验结果。harness 调用计委派深度上限、按工具调用作用域结算；harness:true 工具永远不能脱离 agent 会话独立跑。
guide/tools.md（Harness tools）

§5durable 工具：必须完成的活

进程中途崩掉时，普通在途工具调用不会重跑（runtime 不知道副作用做没做），以 unknown-outcome 错误收场，模型从那儿续。必须完成的活（支付、多步同步、配环境）声明 durable:true，run 拿到 step：

const tenant = await step.do('create-tenant', () => billing.createTenant(customerId));
for (const p of DEFAULT_PROJECTS) await step.do(`seed:${p.name}`, () => projects.seed(tenant.id, p));

恢复时整段重跑，已完成 step 回放记录、从第一个没完成的继续。四条规则：①所有有副作用的进 step；②名字确定性派生（别用随机/时间）；③值保持 JSON 且小（大件存沙箱记指针）；④step 是 exactly-once 记录、at-least-once 执行——围绕外部效果的 step 要各自幂等。
guide/tools.md（Durable tools）· 0009 durability 课将展开整张恢复模型

§6条件工具：把"存在"当程序逻辑

agent 每轮重渲染都从零声明工具集，所以工具在不在只是 if 的事：if (approved) useTool(publishRelease)。没挂载的工具模型根本调不到——比指令说"不许用"更强的保证。工具集在两轮间变了，运行时在下个 turn 边界给模型一条 resources 信号（"新工具可用：…"）。

成本提醒：换工具集 = 重写 provider 的 tools 数组 = prompt cache 失效。所以用「变更少的状态」去 gate 工具；唯一例外是"上一个工具调用解锁下一个"的模式——Anthropic 当前模型（除 Haiku）会在该定义出现处才载入，cache 存活。
guide/tools.md（Conditional tools）· runtime/src/hooks/render.ts（resources 快照）

§7保护访问：参数不是授权边界

工具参数是「模型选的输入」，不是授权边界。让应用先决定工具能用哪个 customer/account/credential，再让模型只在这些值里选。对按客户派发的事件：把应用已校验的标识放投递信号的 attributes，工具里用 useDelivery() 读——模型能选 orderId，但选不了查询用的 customerId。包 provider SDK 时同理：用闭包/配置把 token、仓库钉死，只暴露窄动作。
guide/tools.md（Protect access）· runtime/src/hooks/use-delivery.ts

§8本课自测

本课的胜利：一次工具调用 = 模型见 schema → valibot 解析 → run → 信封回填；三种变体各解决一个问题——harness（摸回运行时）、durable（崩溃不丢活）、条件挂载（存在即逻辑）。
