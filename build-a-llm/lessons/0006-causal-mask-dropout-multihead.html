因果掩码、Dropout 与多头注意力

堵住未来、防止过拟合、拆成多头——三步改造后，我们拿到可以直接插进 GPT 的最终零件：MultiHeadAttention。

§1因果掩码：不许偷看未来

GPT 是自回归模型：预测第 3 个词时只许看前 2 个词。但目前的注意力矩阵是全对称的——"journey" 能看到后面 "one step" 的信息，训练时等于抄答案。因果注意力（causal attention）的解法简单粗暴：把注意力矩阵对角线以上全部屏蔽（书 §3.5.1，图 3.19–3.21）。

工程上最优雅的做法不是"置零再重归一化"，而是利用 softmax 的数学性质——softmax 之前把上三角填成 −∞：

mask = torch.triu(torch.ones(6, 6), diagonal=1)      # 上三角为 1
attn_scores = queries @ keys.transpose(1, 2)
attn_scores.masked_fill_(mask.bool(), -torch.inf)    # 未来位置 → −∞
attn_weights = torch.softmax(attn_scores / d_k**0.5, dim=-1)
# 第 1 行 [1.0, 0, 0, 0, 0, 0] —— Your 只能看自己
# 第 2 行 [0.5517, 0.4483, 0, 0, 0, 0] —— journey 看 Your 和自己

因为 e^(−∞) = 0，被屏蔽位置在 softmax 里自然归零，无需二次归一化——一步到位且无信息泄漏（书 §3.5.1 侧栏"信息泄漏"专门论证了这点）。

——《书》§3.5.1, pp.90–94

§2Dropout：随机关闭注意力

Dropout（dropout）是深度学习的经典抗过拟合手段：训练时随机"关掉"一部分单元，逼模型不依赖任何单一路径。在 GPT 里通常施加在注意力权重算完之后（书采用实践更常见的这种变体）：以概率 p 随机置零部分权重，剩余权重 ×1/(1−p) 放大补偿，保持总量平衡。教学示例用 50% 率，训练真模型时用 0.1–0.2。

dropout = nn.Dropout(0.5)        # 训练时约一半权重被置零、其余×2
attn_weights = dropout(attn_weights)
——《书》§3.5.2, pp.94–96

§3紧凑版 CausalAttention 类

把掩码 + dropout + 批量支持（第 2 课 DataLoader 吐出的 [batch, tokens, dim]）整合进一个类：

class CausalAttention(nn.Module):
    def __init__(self, d_in, d_out, context_length, dropout, qkv_bias=False):
        super().__init__()
        self.d_out = d_out
        self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
        self.W_key   = nn.Linear(d_in, d_out, bias=qkv_bias)
        self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)
        self.dropout = nn.Dropout(dropout)
        self.register_buffer('mask',                       # 掩码不参与训练
            torch.triu(torch.ones(context_length, context_length), diagonal=1))

    def forward(self, x):                    # x: [b, num_tokens, d_in]
        b, num_tokens, d_in = x.shape
        keys    = self.W_key(x)              # [b, num_tokens, d_out]
        queries = self.W_query(x)
        values  = self.W_value(x)
        attn_scores = queries @ keys.transpose(1, 2)       # [b, T, T]
        attn_scores.masked_fill_(                          # 只屏蔽前 num_tokens
            self.mask.bool()[:num_tokens, :num_tokens], -torch.inf)
        attn_weights = torch.softmax(attn_scores / keys.shape[-1]**0.5, dim=-1)
        attn_weights = self.dropout(attn_weights)
        return attn_weights @ values         # [b, num_tokens, d_out]
register_buffer（书 p.97）登记一个不算参数、但会随模型一起搬运的张量（比如移到 GPU 时自动跟着走）——掩码正是这种"随行工具"。GPT-2 的 qkv 偏置为 False（qkv_bias=False），这是对原架构的沿用。
——《书》§3.5.3, pp.96–98（列表 3.3）

§4多头注意力：并联多双眼睛

单头注意力只有一副"q/k/v 眼镜"——它学到的关注模式是单一的。多头注意力（multi-head attention）把机制拆成 num_heads 份并行，每头有独立的投影权重，各自关注不同侧面（语法关系、指代关系、语义相似……），最后把各头输出拼接：

两种实现思路特点
MultiHeadAttentionWrapper堆叠多个 CausalAttention 实例，输出 torch.cat([...], dim=-1)直观但串行、低效
MultiHeadAttention（最终版）一个大 W 投影 → .view 拆成头 → 各头并行算注意力 → 拼回单类集成、矩阵化高效

最终版的关键操作（列表 3.5）：head_dim = d_out // num_heads，投影后的 (b, T, d_out) 张量被 .view 重塑成 (b, T, num_heads, head_dim)、再 .transpose 成 (b, num_heads, T, head_dim)，于是矩阵乘法自动在每个头上并行执行。GPT-2 的配置：768 维 ÷ 12 头 = 每头 64 维。

class MultiHeadAttention(nn.Module):
    def __init__(self, d_in, d_out, context_length, dropout, num_heads, qkv_bias=False):
        super().__init__()
        assert d_out % num_heads == 0, "d_out 必须能被 num_heads 整除"
        self.head_dim = d_out // num_heads
        self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)   # 一次大投影
