第 2 课 · Build a LLM From Scratch · 对应书 §2.1–2.4

分词：文字如何变成数字

读完这一课，你能手工把一句话拆成 token、编成 ID——并理解每个 LLM 入口的那个"翻译官"是怎么工作的。

§1为什么必须"嵌入"

神经网络是一台只懂数字的机器：加法、乘法、矩阵运算。而文字是分类数据（categorical data）——"猫"和"狗"之间没有可计算的数学关系。所以第一步，也是一切的地基：把每个词变成一个连续向量（一串实数）。这个映射就叫嵌入（embedding）。

向量为什么神奇？因为向量之间可以计算"距离"和"方向"。经典的 Word2Vec 训练出的空间里，相似的词会自然聚拢——各种鸟类挤在一起，国家和城市挤在另一处。

本书不走 Word2Vec 的老路：GPT 类模型会在输入层自带一个可训练的嵌入层，随整个模型一起预训练——嵌入因此为"预测下一个词"这个任务量身定制（书 §2.1, p.30）。
——《书》§2.1, pp.28–31

§2第一步：把文本切开（tokenize）

嵌入的对象不是整句话，而是一个个词元（token）。最直觉的切法：按标点和空白切开。书里用正则表达式在短篇小说《The Verdict》上做了一个简易分词器：

import re
text = "Hello, world. This, is a test."
# 按空白、逗号、句号（保留分隔符）切开
preprocessed = re.split(r'([,.:;?_!"()\']|--|\s)', text)
preprocessed = [item.strip() for item in preprocessed if item.strip()]
# → ['Hello', ',', 'world', '.', 'This', ',', 'is', 'a', 'test', '.']

对整篇 20,479 字符的《The Verdict》切下来，得到 4,690 个 token（书 §2.2, p.34）。注意两点：①标点本身也是 token；②不转小写——大小写携带信息（专有名词、句首），丢了可惜。

——《书》§2.2, pp.31–35

§3第二步：词表（vocab）与 token ID

切出 token 后，收集全训练文本中所有不重复的 token，按字母排序，从 0 开始编号——就得到词汇表（vocabulary）。《The Verdict》的词表有 1,130 个词。有了它，任何一段文本都可以编码（encode）成整数序列，也能解码（decode）回来：

vocab = {token: integer for integer, token in enumerate(all_words)}

class SimpleTokenizerV1:
    def __init__(self, vocab):
        self.str_to_int = vocab
        self.int_to_str = {i: s for s, i in vocab.items()}

    def encode(self, text):        # 文本 → token ID 列表
        preprocessed = re.split(r'([,.:;?_!"()\']|--|\s)', text)
        preprocessed = [t.strip() for t in preprocessed if t.strip()]
        return [self.str_to_int[s] for s in preprocessed]

    def decode(self, ids):         # token ID 列表 → 文本
        text = " ".join([self.int_to_str[i] for i in ids])
        return re.sub(r'\s+([,.?!"()\'])', r'\1', text)  # 去掉标点前的空格

编码 "It's the last he painted, you know,"... 得到 [1, 56, 2, 850, 988, ...]——从这一刻起，模型的世界里只有整数。

——《书》§2.3, pp.35–39（列表 2.3）

§4两个问题，两个特殊 token

拿一句训练集里没有的话去 encode——"Hello, do you like tea?"——程序当场崩溃：KeyError: 'Hello'。词表里没有"Hello"。这是真实世界的常态：总会遇到没见过的词。另外，把多篇独立文档拼成一整个训练语料时，模型需要知道"这里换了文档"。

解决方案是往词表里加两个特殊上下文 token（special context tokens）（词表 1,130 → 1,132）：

特殊 token作用
<|unk|>所有词表外的未知词都映射到它
<|endoftext|>拼接语料时插在两篇独立文档之间，标记"上一篇到此结束"；也充当填充（padding）

于是 "Hello, do you like tea?" 编码后解码回来变成 <|unk|>, do you like tea?——"Hello" 被未知 token 顶替了。

——《书》§2.4, pp.40–43
学界还有 [BOS]（序列开始）、[EOS]（序列结束）、[PAD]（批量训练时补齐长度）等常见特殊 token（书 §2.4, p.43）。GPT 分词器做减法：只保留 <|endoftext|> 一个，身兼 EOS 和 PAD 两职——而且连 <|unk|> 都不要。为什么敢不要？这就是下一课的主角 BPE。
