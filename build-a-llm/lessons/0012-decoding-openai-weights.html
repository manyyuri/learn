解码策略与加载 OpenAI 权重

让生成从"复读机"变"有创意"，再把 OpenAI 公开的 GPT-2 权重灌进我们的架构——亲手摸到 124M 参数的真实力量。

§1温度缩放：调节"自信度"

贪心解码永远选第一名，输出呆板。替代方案：概率采样（probabilistic sampling）——按概率抽签（torch.multinomial）。书的例子（9 词小词表，上下文 "every effort moves you"，第一候选 forward 概率约 60%）：

probas = torch.softmax(next_token_logits, dim=0)
next_token_id = torch.multinomial(probas, num_samples=1).item()
# 1000 次采样：582×forward, 343×toward, 73×closer, 2×inches…

温度缩放（temperature scaling）在 softmax 前把 logits 除以温度 T：

def softmax_with_temperature(logits, temperature):
    scaled_logits = logits / temperature
    return torch.softmax(scaled_logits, dim=0)
温度分布形态行为
T → 0.1尖锐（尖峰）≈ argmax，接近贪心，保守
T = 1原始分布按模型本意采样
T = 5平坦（均匀）放飞自我——4% 概率出现 "every effort moves you pizza"
——《书》§5.3.1, pp.176–179（图 5.14）

§2Top-k 采样：创意加护栏

光调温度有风险：高温下低质量词混进来（pizza!）。top-k 采样（top-k sampling）先圈出 logits 最高的 k 个候选，其余全部屏蔽为 −∞（softmax 后概率归零——和第 6 课因果掩码同一个技巧），再在候选内按（可选温度后的）概率采样：

top_logits, _ = torch.topk(logits, top_k)          # k 个最大 logits
min_val = top_logits[:, -1]                        # 门槛：第 k 大的值
logits = torch.where(logits < min_val,
                     torch.tensor(float('-inf')).to(logits.device),
                     logits)                       # 低于门槛 → -inf → 概率 0
# 之后照常：温度缩放 → softmax → multinomial（temperature=0 则退化为 argmax）

最终版 generate() = top-k + 温度 + multinomial +（可选）EOS 提前停止。书的示例 top_k=25, temperature=1.4，输出立刻从背诵原文变成新句子。

——《书》§5.3.2–5.3.3, pp.180–183

§3保存与加载：state_dict

torch.save(model.state_dict(), "model.pth")           # 保存：层名 → 权重 的字典
model = GPTModel(GPT_CONFIG_124M)
model.load_state_dict(torch.load("model.pth", map_location=device))
model.eval()

# 要继续训练？把优化器状态一起存（AdamW 的动量历史丢了收敛会变差）：
torch.save({"model_state_dict": model.state_dict(),
            "optimizer_state_dict": optimizer.state_dict()}, "model_and_optimizer.pth")
——《书》§5.5（中文版编号），pp.184–185

§4灌入 OpenAI 权重：355MB 的下载，一生的技能

自己预训练太贵（Llama 2 7B 约 69 万美元 A100 时，书 p.163 侧栏）。OpenAI 公开了 GPT-2 全系权重——架构完全相同，只是规模不同：

from gpt_download import download_and_load_gpt2
settings, params = download_and_load_gpt2(model_size="124M", models_dir="gpt2")
# settings: {'n_vocab': 50257, 'n_ctx': 1024, 'n_embd': 768, 'n_head': 12, 'n_layer': 12}
# params  : {'blocks', 'b', 'g', 'wpe', 'wte'}  ← TensorFlow 时代的命名

然后三步映射到我们的类：① 用 model_configs 更新配置（124M→768/12/12；355M→1024/24/16…），context_length 改回 1024，qkv_bias 设为 True（OpenAI 的 GPT-2 用了偏置，我们之前按现代规范关了——加载权重必须顺着它）；② assign() 逐张量校验形状并装填；③ 对齐命名差异（OpenAI 的 blocks[0].attn.c_proj.w ↔ 我们的 trf_blocks[0].att.out_proj.weight）。形状不匹配会立即报错——这是防呆设计。

token_ids = generate(model=gpt, idx=text_to_token_ids("Every effort moves you", tokenizer),
                     max_new_tokens=25, context_size=1024, top_k=50, temperature=1.5)
# → "Every effort moves you toward finding an ideal new way to practice
#    something! What makes us want to be on top of that?"

流畅、原创、不是背诵——124M 权重带着全网学到的语言规律住进了你手写的架构。装错了哪怕一个张量，输出立刻乱码——这本身就是最好的验收测试。

——《书》§5.4, pp.186–193（列表 5.5）
