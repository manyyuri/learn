指令微调：从补全机器到听话助手

ChatGPT 的最后一课：用 Alpaca 格式的指令数据训练模型"听懂人话"，再请 Llama 3 当阅卷老师自动打分。

§1补全机器的问题

预训练 GPT 是文本补全机器：给它"把这句改成被动语态"的指令，它大概率接着编下去而不是执行。书里实测：微调前直接问 gpt2-medium 垃圾短信判断，它只会复读问题（第 13 课也见过）。指令微调（instruction finetuning / supervised instruction finetuning）的解法朴素得惊人：拿"指令 + 标准回答"对，继续训练。

——《书》§7.1, pp.234–236

§2Alpaca 格式：指令的模板

数据集：书配套的 1,100 条指令-响应对（204KB JSON），每条含 instruction / input / output 三字段。用 Alpaca 提示样式（Alpaca prompt style）拼成训练文本（斯坦福 Alpaca 首创，另有微软 Phi-3 的 <|user|>/<|assistant|> 风格——本质相同：给指令划好"考场"）：

def format_input(entry):
    instruction_text = (
        "Below is an instruction that describes a task. "
        "Write a response that appropriately completes the request."
        f"\n\n### Instruction:\n{entry['instruction']}"
    )
    input_text = (f"\n\n### Input:\n{entry['input']}"
                  if entry["input"] else "")
    return instruction_text + input_text
# 完整训练文本 = format_input(entry) + f"\n\n### Response:\n{entry['output']}"

85/10/5 切分为训练/验证/测试集。

——《书》§7.2, pp.236–241（图 7.4）

§3自定义 collate：只学回答，不背题目

指令微调批处理最精妙的设计。变长样本按每个批次内最长 pad（不是全数据集最长，省填充）；目标仍是右移一位。关键一步：把"不该学"的目标位置改成 -100：

def custom_collate_fn(batch, pad_token_id=50256, ignore_index=-100,
                      allowed_max_length=None, device="cpu"):
    batch_max_length = max(len(item) + 1 for item in batch)
    inputs_lst, targets_lst = [], []
    for item in batch:
        new_item = item.copy() + [pad_token_id]
        padded = new_item + [pad_token_id] * (batch_max_length - len(new_item))
        inputs  = torch.tensor(padded[:-1])     # 输入
        targets = torch.tensor(padded[1:])      # 目标：右移一位
        mask = targets == pad_token_id
        indices = torch.nonzero(mask).squeeze()
        if indices.numel() > 1:                 # 保留第一个 50256（学"何时停"），
            targets[indices[1:]] = ignore_index # 其余填充位 → -100
        ...
    return inputs_tensor, targets_tensor

为什么是 -100？PyTorch 的 cross_entropy(..., ignore_index=-100) 默认忽略目标为 -100 的位置（书里用 2→3 个 token 的小实验证明：加 -100 目标后损失与不加时完全相同）。于是：pad 不算损失；连指令部分的 target 也可屏蔽——损失只算在 ### Response: 的内容上。模型专心学"怎么答"，不用浪费容量背"怎么抄题目"，还能减少过拟合。保留的那一个 50256 教会模型何时输出结束符（生成时用作停止信号）。

——《书》§7.3–7.4, pp.242–258（列表 7.5，图 7.11–7.13）

§4训练：gpt2-medium + 复用五步咒

这次加载 gpt2-medium（355M）——124M 容量太小学不好听指令（1.42GB 权重，M 系 Mac 需 16GB 内存级别）。训练代码与预训练一模一样：AdamW lr=5e-5、weight_decay=0.1、2 个 epoch、五步咒原样，损失从 2.64 一路降到 0.30。epoch 中途的样文已经像样了：

§5用 LLM 批改 LLM

生成任务没有"分类准确率"这样的客观分。书的方案（AlpacaEval 思路）：让本地跑的 Llama 3 8B（Ollama，REST API）当阅卷老师——给定题目和标准答案，给模型回答打 0–100 分。它能打出"部分分"：明喻题答"快如子弹"给 85 分（合理但不如"闪电"生动）；云类题答"积云"给 40 分（相关但错误——应为积雨云）。

——《书》§7.7–7.8, pp.267–282 —— 1,100 条数据微调出 50+ 分已属高效；82.6 说明海量指令数据 + 大模型的威力。要继续涨：更多数据、更多 epoch 调参、更大底座。

主线在此收官（书 §7.9）：架构 → 预训练 → 加载权重 → 分类微调 → 指令微调，LLM 开发全周期你已走完。此后还有偏好微调（preference tuning，如 DPO）——让回答更对人类胃口，见书 GitHub 04_preference-tuning-with-dpo。
