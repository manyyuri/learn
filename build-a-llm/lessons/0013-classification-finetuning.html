分类微调：GPT 变身垃圾短信侦探

只换一个输出头、只解冻三处参数，5 分钟训练（M3 MacBook）把垃圾短信识别率从 50% 抬到 97.5%——微调性价比的极致示范。

§1两种微调：专才 vs 通才

拿到预训练模型后，把它变成产品的两条路（书 §6.1）：

分类微调（classification finetuning）指令微调（instruction finetuning）
输出固定类别（如 spam / ham）自由生成的文本
能力只会一件事，但很擅长听懂各种指令的通才
数据 / 算力少、便宜多、昂贵
本书位置本课（第 6 章）下一课（第 7 章）

——《书》§6.1, pp.195–197

§2备料：SMS 数据集

UCI 的 SMS Spam Collection：5,572 条短信。两步预处理：

  • 欠采样平衡：ham 4,825 / spam 747 → 各取 747（书选欠采样是为教学省时；实际处理不平衡还有很多方法）
  • 三切分：70% 训练 / 10% 验证 / 20% 测试，标签 ham→0、spam→1

然后解决变长问题：短信长短不一，批处理需要等长——填充（padding）到最长序列（训练集最长 120 token），pad 用的 token ID 是 50256（即 <|endoftext|>，复用第 2 课的特殊 token）。验证/测试集也 pad 到同一长度，超长的截断。

——《书》§6.2–6.3, pp.197–207

§3改造模型：换头 + 三处解冻

先加载 gpt2-small 预训练权重（顺带验证：直接问它"这是不是垃圾短信？"——只会复读问题，因为没做过指令微调）。然后动手术：

for param in model.parameters():
    param.requires_grad = False                    # ① 先全部冻结

model.out_head = torch.nn.Linear(                  # ② 换输出头：50257 → 2
    in_features=BASE_CONFIG["emb_dim"],            #    768 → 2（ham / spam）
    out_features=2)                                #    新层默认 requires_grad=True

for param in model.trf_blocks[-1].parameters():    # ③ 解冻最后一个块
    param.requires_grad = True
for param in model.final_norm.parameters():        # ④ 解冻最终 LayerNorm
    param.requires_grad = True

为什么只解冻尾部？底层捕获通用语言结构（对谁都有用），顶层才需要适配具体任务——省算力还防遗忘。书附录 B 的实验证实多解冻几层能再涨点，但这些是甜点不是主菜。

——《书》§6.4–6.5, pp.207–213（列表 6.7）

§4为什么用最后一个 token？

本课最精彩的一笔。改头后输出是 [b, T, 2]，但只取最后一行（最后 token 的 2 维 logits）算损失。为什么？回看第 6 课的因果掩码矩阵：只有最后一个 token 对所有前文算过注意力——它是全序列信息的汇聚点（书图 6.12）。

logits = model(input_batch)[:, -1, :]              # 只取最后 token → [b, 2]
loss = torch.nn.functional.cross_entropy(logits, target_batch)
# 预测：argmax(logits) → 0 或 1（softmax 可省，理由同第 10 课）
基线检查：未微调时 train/val/test 准确率约 46%/45%/49%——就是抛硬币（两类各半）。微调空间巨大。
——《书》§6.6, pp.217–223

§5训练与验收

训练循环与预训练完全同款（五步咒），只把"打印生成样文"换成"算分类准确率"。AdamW，lr=5e-5（比预训练的 4e-4 小——预训练权重是宝贝，步子要小），5 个 epoch：

最终 classify_review() 实测："You are a winner… $1000 cash" → spam ✅；"Hey, just wanted to check if we're still on for dinner tonight?" → ham ✅。训练曲线 train/val 贴得很近——这次没有第 11 课那种过拟合（数据干净、任务简单、模型早已懂语言）。

——《书》§6.7–6.8, pp.224–233（列表 6.12）

§6检索练习

本课的胜利：你理解了"换头 + 冻结 + 解冻尾部"这套微调手术的标准流程，以及为什么最后一个 token 能代表整条短信。这套技能直接迁移到情感分析、文档分类等一切文本分类任务。
