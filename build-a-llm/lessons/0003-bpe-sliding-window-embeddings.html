BPE、滑动窗口与词嵌入

读完这一课，文字→数字的完整管道全部打通：一块原始文本进去，一组带位置信息的向量出来——这就是喂给 GPT 的"饭"。

§1BPE：永不言"未知"的分词器

简易分词器有个致命伤：词表是封闭的，遇到新词只能投降（<|unk|>）。而 GPT-2、GPT-3 和 ChatGPT 初代使用的字节对编码（BPE, Byte Pair Encoding）思路完全不同：不认识的大词，拆成认识的小块。

BPE 构建词表的逻辑（书 §2.5, p.46）：从全部单字符开始 → 统计哪两个相邻单元最常一起出现 → 合并成新子词（如 d+e→de）→ 重复，直到词表达到目标大小。于是常见词（the）是完整 token，罕见词自动降级为子词序列，最坏也能拆回字符——任何文本都能编码，永不 KeyError。代价：GPT 词表 50,257 个 token，<|endoftext|> 占据最大编号 50256。

import tiktoken                       # OpenAI 官方 BPE 库
tokenizer = tiktoken.get_encoding("gpt2")

text = "Hello, do you like tea? <|endoftext|> In the sunlit terraces of someunknownPlace."
ids = tokenizer.encode(text, allowed_special={"<|endoftext|>"})
# → [15496, 11, 466, 345, 588, 8887, 30, 220, 50256, 554, 262, ...]
print(tokenizer.decode(ids))          # 原文完美复原，包括 someunknownPlace

注意"someunknownPlace"这种生造词被顺利拆成多个子词（some / unknown / Place 的碎片），这正是 BPE 的杀手锏。

——《书》§2.5, pp.44–46

§2滑动窗口：批量制造"输入-目标"对

回忆第 1 课：预训练任务 = 预测下一个词。那么训练数据就是无数的（输入，目标）对。生成方法朴素得优雅：让目标 = 输入右移一位。

enc_sample = [290, 4920, 2241, 287, 257]   # BPE 编码后的片段
x = enc_sample[:4]      # [290, 4920, 2241, 287]   输入
y = enc_sample[1:5]     # [4920, 2241, 287, 257]   目标 = 右移一位

一个长度 4 的窗口里其实藏着 4 道题：[290]→4920、[290,4920]→2241、[…,2241]→287、[…,287]→257。上下文长度（context length）决定窗口大小（书的教育示例用 4，真实训练至少 256）。

窗口沿文本滑动、每次移动的格数叫步长（stride）。stride = max_length 时窗口互不重叠（避免过拟合、充分利用数据）；stride < max_length 时窗口重叠（同样文本产出更多训练样本）。实战用 PyTorch 的 Dataset + DataLoader 封装：

class GPTDatasetV1(Dataset):
    def __init__(self, txt, tokenizer, max_length, stride):
        token_ids = tokenizer.encode(txt)
        self.input_ids, self.target_ids = [], []
        for i in range(0, len(token_ids) - max_length, stride):
            self.input_ids.append(tokenizer[i : i + max_length])       # 窗口
            self.target_ids.append(tokenizer[i + 1 : i + max_length + 1])  # 右移一位

# DataLoader 批量吐出：inputs 形如 [batch, max_length]，targets 同形状
dataloader = create_dataloader_v1(raw_text, batch_size=8, max_length=4,
                                  stride=4, shuffle=True, drop_last=True)
——《书》§2.6, pp.46–54（列表 2.5、2.6）

§3词嵌入：ID 查表变向量

token ID 还是整数，神经网络要的是向量。转换器就是 PyTorch 的 nn.Embedding——本质上是一张可训练的查找表：词表大小 × 嵌入维度 的矩阵，输入 ID 直接取对应行。

vocab_size, output_dim = 6, 3      # 教学示例：6 个词，3 维向量
embedding_layer = torch.nn.Embedding(vocab_size, output_dim)
print(embedding_layer(torch.tensor([3])))   # 返回权重矩阵的第 3 行（从 0 计）

初始权重是随机数，训练中与整个模型一起被反向传播优化——这就是"LLM 自己长出嵌入"的含义。GPT-2 用 50,257 × 768，GPT-3 用 50,257 × 12,288。

——《书》§2.7, pp.54–58

§4位置编码：告诉模型"谁在前谁在后"

还差最后一件事。自注意力机制（下一章主角）有个先天缺陷：它天生不知道词的位置——同一个 token ID 在第 1 位和第 4 位，查表得到的向量一模一样。"狗咬人"和"人咬狗"在它眼里没有区别，这可不行。

GPT 的解法：再加一张可训练的位置查找表（行数 = 上下文长度），第 i 行就是"位置 i"的向量，逐元素加到对应词嵌入上：

token_embeddings = token_embedding_layer(inputs)          # [8, 4, 256]
pos_embeddings = pos_embedding_layer(torch.arange(4))     # [4, 256] 广播到每个样本
input_embeddings = token_embeddings + pos_embeddings      # [8, 4, 256] ← 喂给 LLM！
位置方案有两派：绝对位置嵌入（关心"在第几个位置"，GPT 用这派，且是可训练的）vs 相对位置嵌入（关心"相距多远"，泛化到未见长度更好）。原始 Transformer 用的固定正弦编码是第三种经典方案（书 §2.8, pp.59–60）。
——《书》§2.8, pp.58–63
