模型层：ModelRuntime 与认证

agent 循环要「调模型」，可模型从哪来？哪些模型能用？API key 从哪找？——这些都是 ModelRuntime 的职责。它是 pi-ai 模型目录之上的「运行时外壳」，也是你 SDK 代码里 await ModelRuntime.create() 那个对象。

本课成果：弄清模型目录（catalog）、三层认证来源、可用性快照的语义，以及「你该用哪个对象挑模型」——这些决定了你 workflow 里怎么给不同步骤分配不同模型。

1. 位置与职责

ModelRuntime 在 coding-agent/src/core/model-runtime.ts，实现 pi-ai 的 Models 接口并拥有认证存储（credentials）。职责三块：

  • 模型目录：内置模型元数据 + 自定义模型（models.json）+ 远程目录缓存（models-store.json）
  • 认证：api key / OAuth 的存取与解析
  • 可用性：回答「哪个模型当前真能用」

它不参与 agent 循环——循环只知道「给我一个 Model 对象」，而这个对象由 session 在 prompt() 时从 runtime 选定（第 5 课会看到 hasConfiguredAuth 校验就在 prompt 里）。

2. 目录从哪里来

const modelRuntime = await ModelRuntime.create();          // 默认：恢复本地缓存
const r2 = await ModelRuntime.create({ allowModelNetwork: true, modelRefreshTimeoutMs: 15000 }); // 联网刷新
await modelRuntime.refresh({ allowNetwork: true, force: true, signal }); // 主动强制刷新

要点（sdk.md + 源码核实）：

  • create() 默认只恢复本地缓存的目录，不联网。想首次联网拉目录，显式开 allowModelNetwork 并给它一个超时。
  • 网络刷新按 provider 每 4 小时节流一次，除非 force: true。
  • PI_OFFLINE 关闭一切模型网络访问。
  • 目录持久化在 ~/.pi/agent/models-store.json（可换 modelsStorePath）。

3. 认证的三层来源

「这个 provider 有没有 key？」的解析优先级（sdk.md 明示）：

优先级来源
1运行时覆盖 setRuntimeApiKey(provider, key)（不落盘，测试/临时 key 用它）
2存储的凭据 ~/.pi/agent/auth.json（api key 或 OAuth token，由 login/logout 维护）
3环境变量 ANTHROPIC_API_KEY 等
4fallback 解析器（models.json 里自定义 provider 的 key 模板）

可换目录：ModelRuntime.create({ authPath, modelsPath })，甚至注入任意 pi-ai 的 CredentialStore（如 InMemoryCredentialStore）。这行 API 是你做无副作用测试/多租户隔离的入口。

4. 三个容易混的方法

方法含义何时用
getModel(providerId, modelId)按 id 从目录找，不检查有没有 key你想指定某个已知模型
getAvailable(providerId?)只返回已配好认证的模型给用户列「现在真能用哪些」
checkAuth(providerId) / hasConfiguredAuth查该 provider 的认证状态prompt 前的 auth 校验（session 内部）
为什么区分：目录里模型再多，没 key 也调不动。getModel 答「存在吗」，getAvailable 答「能用吗」——你的 workflow 若是「自动选默认模型」，应该走 getAvailable 而不是 getModel，否则会选到没 key 的模型然后 prompt 抛错。

5. CLI 解析器：把字符串变成模型 + 思考等级

coding-agent 导出了两个解析器，把「anthropic/claude-opus-4-5:high」这种字符串解析成模型与 thinkingLevel：

const { model, error, warning } = resolveCliModel({ cliModel: "anthropic/claude-opus-4-5:high", modelRuntime });
const { scopedModels, diagnostics } = await resolveModelScopeWithDiagnostics(["anthropic/*:high", "gpt-5"], modelRuntime);

你的 workflow 如果允许用户用配置字符串指定某一步的模型，这两个函数就是现成的解析器——语法、错误信息都和 pi CLI 一致，不用自己再造。
