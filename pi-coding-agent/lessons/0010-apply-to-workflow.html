综合：把九课的知识用回你的 workflow

前九课是「地图」，这一课是「导航」：把这些架构约束翻译成你那个「从需求澄清到测试报告」的固定流程应用里的一组设计决策。没有新源码，只有决策。

本课成果：拿到一张「workflow 设计自检表」，能用它审视你现有实现：哪里做得对、哪里踩了架构约束、哪里可以更省。

0. 九十秒回顾（九课压成一段话）

一次 prompt = 一串回合。 Agent 核心对着 state（messages/model/tools/systemPrompt）跑到没活干，把工具结果当消息回灌；Agent 单飞，流式时只能 steer/followUp。Session 是监护人：进门先过命令/模板/拦截/auth/压缩检查，出门做 retry/compaction 再发 agent_settled。资源由 ResourceLoader 发现，会话是 SessionManager 里一棵能分支的树，模型来自 ModelRuntime。以上全部，mode 只是驾驶舱，SDK 与它同源。

1. 第一个决策：步骤用「一个长会话」还是「每步新会话」

这是你 workflow 最核心的架构选择，用九课学到的约束来对答案：

A. 一个 AgentSession 串到底B. 每步新建 AgentSession
上下文全历史共享；长了靠 compaction（阈值 = 窗口−预留 16k）每步干净；跨步上下文需显式传递
单飞影响同会话天然串行，一次一个 run不同 session 可并行（互不阻塞）
工具/模型步骤间需手改 state（setModel / 换 state.tools）每步 createAgentSession 时各配各的，天然隔离
污染风险上一步的杂讯留在上下文，可能带偏下一步低——每步只看到你喂进去的
断点续跑天然（session 文件/树）需自己持久化步骤产物做检查点
给你的倾向（可用你的真实场景推翻）：固定 pipeline + 各步职责差异大（澄清 vs 建模 vs 测试）→ B 更干净：每步一个短命 session，工具/模型各配，跨步只传「上一层的结论摘要 + 产物路径」。只有当你的某几步确实需要「记得整段对话」时才为那几步改用 A 或复用同一 session。

2. 如果选 B：跨步传什么？

第 6、7 课给了你现成范式——压缩总结与 branch_summary 的格式就是「给续作 LLM 的上下文」的范本。跨步上下文别塞原始对话，传：

  • 结构化结论（需求要点、决策、产出物路径），像 checkpoint 总结那样写给下一步的模型看
  • 产物引用：测试报告、代码在磁盘哪，让下一步 agent 用 read 工具自己读（呼应第 8 课「按需读文件省窗口」）
  • 约束与待办：哪些别改、哪些必做

实现上：每步用 SessionManager.inMemory() 或持久化到独立 jsonl，作为该步检查点；步骤衔接用你编排层自己的「步骤产物对象」，不靠会话树跨 session（树是文件内的）。

3. 若干具体的架构坑（对应前九课）

坑第几课的约束对策
步骤提示词以 / 开头，被当成命令吞掉⑤ prompt 管线第 1 步避免裸 / 开头；或检查扩展命令表
长步骤中途用户想插话，直接再 prompt() 抛错② single-flight用 steer()（插话）或 followUp()（续跑）
步骤没配 key，模型跑一半才报错④ auth 前置校验步骤前用 modelRuntime.getAvailable() 预检，给干净错误
选了目录里有但没 key 的模型④ getModel vs getAvailable自动选型一律走 getAvailable
把「agent_end」当「跑完」，统计/落库提前①⑤ settled 语义收尾逻辑等 agent_settled，或 await prompt()（它含 retry/compaction）
上下文越长越慢还偶发截断（stopReason length）⑥ compaction / ③ 截断整批失败长步骤用 B 模式保持上下文短；或接受 compaction
想并行两个 agent 步骤，共用一个 session② single-flight 禁止两个独立 AgentSession 并行，各自 inMemory

4. workflow 设计自检表（拿去用）

  • ☐ 每一步的「输入上下文」我明确知道是哪几条消息吗？（不靠隐式全历史）
  • ☐ 跨步传递的是「结构化结论 + 产物引用」而不是原始对话吗？
  • ☐ 每步的工具集 / 模型 / 思考等级是否按需配置、互不越界？
  • ☐ 有 auth 预检，没配 key 不会到模型那步才炸吗？
  • ☐ 步骤完成信号用的是 settled/prompt resolve 而非 agent_end 吗？
  • ☐ 长任务有断点（持久化产物/标签），失败能从中断处续跑吗？
  • ☐ 需要并行的步骤用了独立 session 吗？
  • ☐ 提示词不会误触发 /命令 / skill 块展开吗？
