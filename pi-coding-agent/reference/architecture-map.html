一次 prompt 的旅程

session.prompt(text)
 ├─ 前处理: /命令? → skill/模板展开 → 扩展input拦截
 │          → 流式检查 → model/auth 校验 → 压缩检查
 └─ agent.prompt(user消息)
     └─ runLoop:  agent_start · turn_start · 消息入队/注入
         ┌─ 内层 while: 调LLM流式 → message_update(text/toolcall)
         │    message_end → 有 toolCall?
         │       是 → 执行工具(parallel默认) → toolResult 回灌 → 再来一回合
         │       否 → turn_end → steering队列空? → 内层退出
         └─ 外层: followUp队列非空? → 再开一批回合
             否 → agent_end
 └─ session 后处理: retry? → compaction? → agent_settled

事件 ↔ 谁在发出

事件拍点层
agent_start / agent_endrun 首尾agent
turn_start / turn_end回合边界（一次 run 多个）agent
message_start / update / end消息诞生/流式/定型入 transcriptagent
tool_execution_start/update/end工具执行前后agent
agent_settledretry/compaction 决策后session
queue_update · auto_retry_* · compaction_*队列 / 重试 / 压缩session

三条反直觉约束

  • 单飞：一个 Agent 同时只跑一个 run；流式时 prompt() 抛错 → 用 steer（插话）/ followUp（停后再跑）
  • 上下文 = 消息序列：工具结果是被包成 toolResult 的消息回灌，不是旁路数据；custom 角色默认不进 LLM（convertToLlm 过滤）
  • Session 是监护人：命令/模板/拦截/auth/retry/compaction/settled 都在 session 层，Agent 核心只管跑循环

关键数字（默认）

compaction:  contextTokens > 窗口 − 16k(reserveTokens) 触发
             cut 后保留最近 ~20k(keepRecentTokens)，旧消息压成结构化总结
工具执行:    parallel 默认；任一工具标 sequential 则整批串行
             stopReason="length"(截断) → 整批工具判失败
认证优先级:  setRuntimeApiKey > auth.json > 环境变量 > models.json fallback
目录:        ModelRuntime.create() 默认只读本地缓存；联网需 allowModelNetwork

workflow 决策速记

固定多步 pipeline  → 每步独立 AgentSession（上下文干净、可并行、工具模型各配）
跨步传上下文      → 结构化结论 + 产物路径引用（让下步 read 按需读）
步骤完成信号      → agent_settled / await prompt()（含 retry），不是 agent_end
并行步骤          → 独立 session；同一个 session 无法同时跑两个 run
模型自动选型      → getAvailable（有认证的），不是 getModel（只在目录）

术语：run=一次 prompt/continue 的完整过程；turn=一次 LLM 响应+其工具执行；single-flight=单飞；compaction=压缩；mode=驾驶舱。
